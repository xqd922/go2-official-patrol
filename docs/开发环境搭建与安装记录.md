## 2. 一键复现流程（全新机器）

以下命令按顺序执行即可复现整套环境（脚本已修复，本机已验证通过）。

```bash
# ---------- 1. 基础工具与 ROS 2 源 ----------
sudo apt update
sudo apt install -y curl gnupg lsb-release software-properties-common
sudo add-apt-repository -y universe

sudo curl -sSL https://raw.githubusercontent.com/ros/rosdistro/master/ros.asc -o /tmp/ros.asc
sudo gpg --dearmor -o /usr/share/keyrings/ros-archive-keyring.gpg /tmp/ros.asc
echo "deb [arch=amd64 signed-by=/usr/share/keyrings/ros-archive-keyring.gpg] http://packages.ros.org/ros2/ubuntu jammy main" \
  | sudo tee /etc/apt/sources.list.d/ros2.list > /dev/null
sudo apt update

# ---------- 2. 安装 ROS 2 Humble ----------
sudo apt install -y ros-humble-desktop
sudo apt install -y python3-rosdep
sudo rosdep init || echo "rosdep already init"
rosdep update
echo "source /opt/ros/humble/setup.bash" >> ~/.bashrc

# ---------- 3. 复制工作空间到 WSL 家目录 ----------
mkdir -p ~/go2_official_ws
cp -a /mnt/d/Desktop/robot/dog/go2_official_ws/. ~/go2_official_ws/
chmod +x ~/go2_official_ws/scripts/*.sh

# ---------- 4. 一键装项目依赖 + 拉官方仓库 + 编译 ----------
cd ~/go2_official_ws
./scripts/bootstrap.sh

# ---------- 5. 屏蔽不需要的官方示例包（避免 OOM，见问题 8） ----------
touch ~/go2_official_ws/src/unitree_ros2/example/COLCON_IGNORE
colcon build --symlink-install

# ---------- 6. 验证 ----------
python3 -m pytest src -q
source scripts/setup.sh
ros2 topic list
```

## 4. 问题与修复记录（重点）

### 问题 1：wsl --install 报“已存在具有所提供名称的分发”

- 现象：

```
PS> wsl --install -d Ubuntu-22.04
已存在具有所提供名称的分发。使用 --name 选择其他名称。
错误代码: Wsl/InstallDistro/ERROR_ALREADY_EXISTS
```

- 原因：Ubuntu-22.04 这个发行版已经装过了，--install 想重新装，所以报错。
- 解决：不是错误，不用重装，用 `wsl -d Ubuntu-22.04` 进入即可。

### 问题 2：E: Unable to locate package ros-humble-desktop

- 现象：直接 `apt install ros-humble-desktop` 找不到包。
- 原因：Ubuntu 默认软件源不含 ROS 2，必须先添加 ROS 2 官方源和密钥。
- 解决：先做第 3.2 节“添加 ROS 2 软件源”再安装。

### 问题 3：sudo 密码与自动化脚本（重要教训）

- 现象：`bootstrap.sh` 里有多条 sudo 命令；自动化执行时卡在密码提示，整个脚本挂起。
- 原因：sudo 的时间戳缓存默认按 tty 绑定（timestamp_type=tty），
  每次 `wsl -d Ubuntu-22.04 -- bash -c ...` 都是新终端，之前的缓存全部失效。
- 解决（自动化用）：在同一个 bash 会话里先刷新凭据，再在同一会话立即执行脚本：

```bash
echo <密码> | sudo -S -v && cd ~/go2_official_ws && ./scripts/bootstrap.sh
```

- 注意：
  - 会把明文密码留在 shell 历史，不要写进仓库或共用脚本；
  - 更稳妥的做法：先把所有 apt 依赖包手动装好，再跑脚本（此时脚本里的 apt 是秒过的 no-op）。

### 问题 4（工程 bug）：bootstrap.sh 里 vcs import 目录多套一层

- 现象：官方仓库被克隆到了 `src/src/unitree_ros2`，脚本随后报：

```
./scripts/bootstrap.sh: line 13: cd: src/unitree_ros2/cyclonedds_ws: No such file or directory
```

- 原因：`.repos` 文件的键是相对工作空间根的 `src/unitree_ros2`，
  但脚本写成 `vcs import src < repos/...`（相对 src 目录导入），路径就变成了 src/src/...。
- 修复（scripts/bootstrap.sh）：

```diff
- vcs import src < repos/go2_official_ws.repos
+ vcs import < repos/go2_official_ws.repos
```

- 同时把已经克隆错位置的目录移回正确位置（已在本机处理）。

### 问题 5（工程 bug）：bootstrap.sh 里 cd 路径回不到工作空间根

- 现象：编译完 cyclonedds_ws 后，第二条 colcon build 会跑在 `src/` 目录里，
  而不是工作空间根，install 目录位置与 setup.sh 的预期（~/go2_official_ws/install）不一致。
- 原因：`cd ../..` 只能从 `src/unitree_ros2/cyclonedds_ws` 回到 `src/`，需要回三层。
- 修复（scripts/bootstrap.sh）：

```diff
- cd ../..
+ cd ../../..
```

### 问题 6（工程 bug）：set -u 与 ROS 2 setup.bash 冲突

- 现象：脚本执行到 `source /opt/ros/humble/setup.bash` 时报：

```
/opt/ros/humble/setup.bash: line 8: AMENT_TRACE_SETUP_FILES: unbound variable
```

脚本随即退出（set -e）。
- 原因：脚本用了 `set -euo pipefail`，`-u` 会在引用未定义变量时报错退出；
  ROS 2 的 setup.bash 内部引用了未定义的 AMENT_TRACE_SETUP_FILES，两者冲突。
- 修复：source 前后临时关闭 -u。`bootstrap.sh` 和 `setup.sh` 两个脚本都改了：

```bash
set +u
source /opt/ros/humble/setup.bash
set -u
```

### 问题 7（工程 bug）：package.xml 邮箱非法导致编译失败

- 现象：

```
Invalid email "dev@local" for person "Go2 Patrol"
CMake Error: ... go2_patrol_bringup ... returned error code 1
Failed <<< go2_patrol_bringup
```

- 原因：catkin_pkg 校验 package.xml 时要求邮箱域名带点，`dev@local` 不合法。
- 修复：4 个 package.xml + 3 个 setup.py 里 `dev@local` 全部改为 `dev@example.com`。

### 问题 8（环境）：编译 unitree_ros2_example 时内存不足被系统杀掉

- 现象：

```
c++: fatal error: Killed signal terminated program cc1plus
gmake[2]: *** [...] Error 1
Failed <<< unitree_ros2_example
```

- 原因：WSL 只有 6.6 GB 内存，而 colcon 用 -j16 并行编译官方示例包
  （几十个重型 C++ 示例），内存耗尽后 OOM killer 杀掉了编译器进程。
- 解决（两步）：
  1. .wslconfig 把 WSL 内存调到 10 GB；
  2. 官方示例包与巡检项目无关，直接跳过：

```bash
touch ~/go2_official_ws/src/unitree_ros2/example/COLCON_IGNORE
```

- 预防：以后新增重型 C++ 包编译时，如内存紧张可降低并行度，如
  `MAKEFLAGS=-j4 colcon build`。

### 问题 9（环境）：install/ 里残留脏引用

- 现象：source install/setup.bash 时报：

```
not found: "/home/seven/go2_official_ws/install/unitree_ros2_example/share/unitree_ros2_example/local_setup.bash"
```

导致 setup.sh 中断退出。
- 原因：之前 unitree_ros2_example 构建失败，但 install/ 里留下了它的注册信息，
  setup 链式脚本仍然引用它。
- 解决：彻底清理构建产物后全量重编：

```bash
cd ~/go2_official_ws
rm -rf build install log
source /opt/ros/humble/setup.bash
colcon build --symlink-install
```

- 预防：只要示例包有构建失败残留，先清 build/install/log 再编，不要带着脏产物往前跑。

### 问题 10（工程 bug）：setup.sh 网卡名写死导致 WSL 里 DDS 建域失败

- 现象：`ros2 topic list` 报：

```
ros2: enp3s0: does not match an available interface.
[ERROR] [rmw_cyclonedds_cpp]: rmw_create_node: failed to create domain, error Error
```

- 原因：setup.sh 默认 GO2_IFACE=enp3s0（真机有线网卡名），
  但 WSL 里的网卡叫 eth0，CycloneDDS 找不到接口直接建域失败。
- 修复（scripts/setup.sh）：改为自动检测默认路由网卡，GO2_IFACE 仍可显式覆盖：

```bash
IFACE="${GO2_IFACE:-}"
if [ -z "$IFACE" ]; then
  IFACE="$(ip route show default 2>/dev/null | awk '/default/ {print $5; exit}')"
fi
IFACE="${IFACE:-enp3s0}"
```

- 效果：WSL 里自动用 eth0；真机上建议仍然显式 `export GO2_IFACE=<有线网卡>`，
  因为真机默认路由很可能是 WiFi 而不是连机器狗的那根网线。

### 问题 11（预防性）：CRLF 换行符隐患

- 现象：git 在 Windows 上提示 `LF will be replaced by CRLF`。
- 风险：shell 脚本一旦被转成 CRLF，在 Linux/WSL 下会报
  `/usr/bin/env: 'bash\r': No such file or directory` 之类的 bad interpreter 错误。
- 解决：新增 .gitattributes：

```
* text=auto
*.sh text eol=lf
```

### 问题 12（工程 bug）：mapping / navigation launch 缺 Node 导入，启动即崩

- 现象：`ros2 launch go2_patrol_bringup mapping.launch.py` 直接失败：

```
[ERROR] [launch]: Caught exception in launch (see debug for traceback):
 - NameError: name 'Node' is not defined
```

- 原因：`mapping.launch.py` 和 `navigation.launch.py` 都用了 `Node(...)`
  却没有 `from launch_ros.actions import Node`，运行期 NameError。
- 修复：两个文件补上该导入。
- 备注：这两个是建图/导航的主入口文件，不修的话真机上也无法启动。
  （离线演示时实际踩到并修复。）

### 问题 13（工程 bug）：odom_bridge 收到消息即崩（numpy.float32 断言）

- 现象：odom_bridge 一收到 `/lf/sportmodestate` 就退出：

```
File ".../geometry_msgs/msg/_quaternion.py", line 169, in x
  assert ...
AssertionError: The 'x' field must be of type 'float'
```

- 原因：Humble 的 rclpy 对 `float32[]` 字段返回 `numpy.ndarray`，
  元素是 `numpy.float32`（不是 Python float 子类），而 `Quaternion.x`
  的 setter 断言要求严格 float。odom_bridge 的 IMU 分支直接
  `imu.orientation.x = q[0]`，没有做转换。
- 验证：

```
quaternion type: <class 'numpy.ndarray'>
element type:    <class 'numpy.float32'>
```

- 修复：IMU 分支加 `float()` 转换（`float(q[0])` 等）；其余分支原本就有 float()。
- 备注：真机上消息路径相同，同样必崩，属关键修复。

### 问题 14（工程 bug）：save_map.sh 两个小问题

1. 新终端直接运行报 `ros2: command not found` —— 脚本不加载 ROS 环境。
   修复：检测不到 ros2 时自动 source `scripts/setup.sh`。
2. `name` 参数带了 `.yaml` 后缀，slam_toolbox 保存时再补一次扩展名，
   产出 `demo_room.yaml.yaml` / `demo_room.yaml.pgm` 双后缀文件。
   修复：name 只传路径、不带扩展名，得到标准的 `demo_room.yaml` + `demo_room.pgm`。

### 问题 15（环境）：WSLg 窗口"登记但不显示"——RViz 看不到界面

- 现象：RViz/xeyes 等 GUI 程序的进程正常、X11 里窗口存在（`xwininfo` 可见），
  但 Windows 桌面上完全看不到窗口，截图确认没有绘制到屏幕上。
  窗口标题带 `[WARN:COPY MODE]` 前缀（图形加速降级标志）。
- 原因：WSLg 的合成器（msrdc 进程/Weston 通道）故障，
  应用窗口只完成了 X11 层登记，从未合成到 Windows 桌面。
  单纯重启应用、重启 msrdc 进程、重启单次 bash 会话都无法修复。
- 解决：完全重启 WSL（重置整个 WSLg 通道）：
  ```powershell
  wsl --shutdown
  ```
  等待约 8 秒后重新进入 WSL，GUI 恢复正常
  （xeyes 测试窗口标题不再带 [WARN:COPY MODE]，且能真实显示）。
- 验证方法：
  1. `xwininfo -root -tree | grep rviz` 在 WSL 里能看到窗口 → X11 层正常；
  2. Windows 侧枚举可见窗口（EnumWindows）如果找不到 RViz → WSLg 层故障；
  3. 重启 WSL 后重新启动演示，窗口正常显示。
- 备注：WSL 重启后之前所有 nohup 启动的进程都会被清掉，
  重新跑 `tools/offline_demo/run_demo.sh start` 即可。

## 8. Windows 与 WSL 的代码同步

现状是两份拷贝：Windows 侧仓库用于编辑/Git，WSL 侧用于编译运行。
修改 Windows 侧后，同步到 WSL（按需复制目录即可）：

```bash
# 同步全部源码（不含 unitree_ros2 官方克隆，避免覆盖）
rsync -a --exclude unitree_ros2 /mnt/d/Desktop/robot/dog/go2_official_ws/src/ ~/go2_official_ws/src/

# 只同步某个包（例）
```

### 问题 16（环境）：RViz 界面卡死（远程桌面 + WSLg 双重转发的渲染压力）

- 现象：RViz 开着 3D 点云显示后界面卡死（转视角/缩放无响应）。
- 排查过程与更正：
  1. 曾怀疑"无 GPU 直通导致软件渲染"——**误判**。实际检查：
     ```bash
     glxinfo -B | grep renderer
     # OpenGL renderer string: D3D12 (AMD Radeon(TM) 680M)   <= GPU 正常
     ls /dev/dxg    # crw-rw-rw- 存在；WSL 用 /dev/dxg 而不是 /dev/dri
     ```
  2. 曾看到"msrdc CPU 100%"——**误读**。Windows 的 `Process.CPU` 是
     **累计 CPU 时间（秒）**，不是占用率；应用排队时间换算后并不异常。
- 更可能根因：本机通过**远程控制软件**（检测到 GameViewer/ToDesk/RustDesk
  进程与虚拟显示器 GameViewer Virtual Display Adapter）远程操作。
  画面链路 = RViz 渲染 → WSLg 合成(msrdc) → 远程桌面编码传输，
  双重转发叠加 10Hz 全屏 3D 重绘，远程管道容易饱和卡死。
- 缓解方法（按优先级）：
  1. RViz 用小窗口（约 1000x700）代替全屏，别长时间开着转视角；
  2. 演示时关掉 PointCloud2_RAW（点云全帧重绘最重），只留 /scan + Map；
  3. 假数据频率可降到 5Hz（fake_go2.py 的定时器 1/10 -> 1/5）；
  4. 需要确认画面时优先**截图检查**（WSL 内 `import -window <id>` 截图），
     不依赖实时窗口交互；
  5. 应急恢复：kill rviz2；若图形层异常则 `wsl --shutdown` 完全重启。
- 结论：这是远程观看环境的性能限制，不是环境配置错误；
  真机现场直接在物理屏前操作不会有此问题（或本地使用体验正常）。
### 问题 17（配置）：WSL2 默认 NAT 网络无法连真机 —— 已切换镜像网络

- 背景：ROS 2 用 CycloneDDS 做节点发现（依赖组播）。WSL2 默认 NAT 模式下
  组播包出不了 WSL 也进不来，局域网里的 Go2（192.168.123.161）根本发现不了，
  `/lf/sportmodestate`、`/utlidar/cloud_deskewed` 一条都收不到。
- 处理（2026-10-14）：`C:\Users\Seven\.wslconfig` 增加两行并重启 WSL：

```ini
networkingMode=mirrored   # WSL 直接共享主机网卡
firewall=false            # 关闭 Hyper-V 防火墙对 WSL 流量的过滤
```

- 生效后验证（PowerShell 执行 `wsl --shutdown` 重启后，在新终端执行）：

```bash
# 1. WSL 里应能看到与 Windows 相同的网卡（如 WLAN / 以太网）：
ip -brief addr

# 2. WiFi 连狗热点或网线接狗后，应能 ping 通机器狗：
ping -c 3 192.168.123.161

# 3. 按实际接狗网卡指定接口后再 source（名字以 ip -brief addr 为准）：
export GO2_IFACE=WLAN

ros2 topic hz /lf/sportmodestate
```

  显式指定接狗的那块，否则默认路由网卡可能不是它。
