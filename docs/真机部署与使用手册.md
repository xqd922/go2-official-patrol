# Go2 巡检系统：真机部署与使用手册

> 适用对象：准备让宇树 Go2 在真实场地执行建图、导航、航点巡检和语音播报的人员。
>
> 本文以当前仓库代码和脚本为准。真机链路尚未在本工作空间中完成最终现场验收，
> 因此所有速度、急停距离、固定起点和点位都必须按实际机器、地面和负载重新标定。

## 1. 先明确系统形态

本项目默认采用“机器狗 + 外接控制电脑”的形态：

```text
Go2 本体与机载雷达
        │ 网线
        ▼
控制电脑（Ubuntu 22.04，或 Windows + WSL2）
  ├─ 接收 /lf/sportmodestate、/lf/lowstate、/utlidar/cloud_deskewed
  ├─ 建图 / 定位 / Nav2 规划
  ├─ 航点巡检与语音播放
  └─ 向机器狗发送 /api/sport/request
```

代码运行在控制电脑上，不安装进 Go2 机载系统。生产交付通常是一台固定在现场的
Ubuntu 工控机或迷你主机。

### 1.1 必需的软硬件

| 项目 | 要求 |
|---|---|
| 机器狗 | 宇树 Go2，官方 ROS 2 数据链可用，遥控器随车 |
| 控制电脑 | Ubuntu 22.04 推荐；或 Windows 11 + WSL2 镜像网络 |
| ROS | ROS 2 Humble Desktop |
| 网络 | 控制电脑与 Go2 有线直连；默认狗地址 `192.168.123.161` |
| 雷达 | 机载 4D 雷达 L1 或 L2，话题接口相同 |
| 音频 | 控制电脑有可用扬声器，或生产机已配置音频设备 |
| 官方依赖 | `unitree_ros2`，由 `scripts/bootstrap.sh` 按固定提交拉取 |

### 1.2 真机和仿真的边界

离线演示能验证节点启动、Nav2、巡检状态机、播报和站点参数链路，
但**不能证明**真机网卡、DDS 通信、TF 发布关系、实际急停距离和定位效果。
真机首次运行必须完成本文第 9、10 节的现场检查。

## 2. 首次上机的最短路径

严格按顺序执行，不要跳步：

1. 安装并编译工作空间。
2. 配置接狗网卡、IP 和 CycloneDDS。
3. 确认运动状态和点云都有频率。
4. 遥控机器狗完成一次建图并保存地图。
5. 用静态地图启动导航，完成一次近距离单点导航。
6. 标定固定起点、巡检点位和语音。
7. 用站点方式启动巡检并做安全验收。
8. 需要无人值守时，再安装 systemd 服务。

## 3. 安装与编译

### 3.1 将仓库放到 Linux 家目录

ROS 2 和 `colcon` 不要直接在 Windows PowerShell 中运行。若仓库目前位于
`D:\Desktop\robot\dog\go2_official_ws`，可在 WSL/Ubuntu 中复制一份：

```bash
mkdir -p ~/go2_official_ws
cp -a /mnt/d/Desktop/robot/dog/go2_official_ws/. ~/go2_official_ws/
cd ~/go2_official_ws
chmod +x scripts/*.sh deploy/*.sh tools/offline_demo/*.sh
```

### 3.2 一次性安装依赖并编译

以下步骤假设控制电脑已经安装 ROS 2 Humble Desktop。若 `/opt/ros/humble/setup.bash`
不存在，请先按 ROS 2 官方文档安装 Humble，再执行本节的依赖和编译脚本。

```bash
cd ~/go2_official_ws
./scripts/bootstrap.sh
```

脚本会完成：

- 安装 `deploy/apt-deps.txt` 中的 ROS 2/Nav2/SLAM Toolbox 等依赖；
- 从 `repos/go2_official_ws.repos` 拉取固定版本的 `unitree_ros2`；
- 编译 `unitree_ros2/cyclonedds_ws`；
- 编译本工作空间。

### 3.3 每个新终端加载环境

```bash
cd ~/go2_official_ws
GO2_IFACE=<接狗网卡名> source scripts/setup.sh
```

正常会打印类似摘要：

```text
[go2_env] WS=/home/seven/go2_official_ws SITES=.../sites IFACE=enp3s0 DOG=192.168.123.161
```

多网卡电脑必须显式设置 `GO2_IFACE`。默认路由网卡通常不是接机器狗的那张网卡。

### 3.4 WSL2 额外配置

WSL2 默认 NAT 网络收不到机器狗组播。编辑 `C:\Users\<用户名>\.wslconfig`：

```ini
[wsl2]
memory=10GB
networkingMode=mirrored
firewall=false
```

然后在 PowerShell 中执行：

```powershell
wsl --shutdown
```

重新进入 WSL 后，用 `ip -brief addr` 确认能看到与 Windows 相同的接狗网卡。

`networkingMode=mirrored` 和 `firewall=false` 只是必要条件，实测还差下面三处，
否则会出现“`ping 192.168.123.161` 通、`ros2 topic list` 只有 `/rosout`”的假连通状态。
四件事缺一不可。

#### 3.4.1 放行 Hyper-V 防火墙的入站流量

`firewall=false` 只关闭 WSL 自己的规则，Hyper-V 防火墙仍会丢弃发往 WSL 的入站包。
DDS 的数据端口是动态分配的，只放行 7400-7440 不够，必须放行全部入站。
以**管理员 PowerShell**执行一次：

```powershell
$vm = '{40E0AC32-46A5-438A-A0B2-2B479E8F2E90}'
New-NetFirewallHyperVRule -Name 'WSL-DDS-In-Any' `
  -DisplayName 'WSL DDS inbound any' `
  -Direction Inbound -VMCreatorId $vm -Protocol Any
```

检查与删除：

```powershell
Get-NetFirewallHyperVRule | Where-Object Name -like 'WSL-DDS-*'
Get-NetFirewallHyperVRule | Where-Object Name -eq 'WSL-DDS-In-Any' | Remove-NetFirewallHyperVRule
```

#### 3.4.2 把组播路由指向接狗网卡

WSL 内 `239.255.0.1` 的组播路由默认跟随默认路由（通常是 Wi-Fi 或 TUN 网卡），
会走错网卡，导致机器人的 DDS 广播收不到。接狗网卡名在 WSL 里通常是 `eth7` 这类
动态名字，因此按 MAC 识别，而不是写死网卡名。

创建 `/usr/local/sbin/go2-mcast-route.sh`：

```bash
#!/bin/bash
set -euo pipefail
GO2_MAC="00:e0:2a:89:3f:b5"
IFACE=$(ip -br link | awk -v m="$GO2_MAC" '$3==m {print $1; exit}')
if [ -z "${IFACE:-}" ]; then
  echo "go2-mcast-route: adapter $GO2_MAC not present" >&2
  exit 0
fi
ip route replace 239.255.0.0/16 dev "$IFACE"
echo "go2-mcast-route: 239.255.0.0/16 -> $IFACE"
```

再用 systemd 开机自动执行：

```bash
sudo chmod 755 /usr/local/sbin/go2-mcast-route.sh
sudo tee /etc/systemd/system/go2-mcast-route.service >/dev/null <<'EOF'
[Unit]
Description=Go2 DDS multicast route (WSL mirrored)
After=network-online.target
Wants=network-online.target

[Service]
Type=oneshot
ExecStart=/usr/local/sbin/go2-mcast-route.sh
RemainAfterExit=yes

[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload
sudo systemctl enable --now go2-mcast-route.service
```

验证：

```bash
ip route get 239.255.0.1
# 期望：multicast 239.255.0.1 dev eth7 src 192.168.123.99
```

#### 3.4.3 不要开着 Clash 等代理的 TUN 模式

代理 TUN 会插入一块 `eth8`（`198.18.0.1/30`）并抢占默认路由（metric 1），
组播也会被带走。开机或联调前关闭 TUN；只开系统代理也会留下
`ProxyEnable=0` 但 `ProxyServer` 非空的残留值，需要一并清掉：

```powershell
Set-ItemProperty -Path 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings' -Name ProxyServer -Value ''
```

排查时用 `ip -brief addr` 看是否多出 `198.18.x.x` 网卡，用
`ip route get 239.255.0.1` 看出口网卡是否正确。

完整的排错过程、原理验证和实测数据见
[WSL2 连接 Go2 完整排错与联调实录](./WSL2连接Go2完整排错与联调实录.md)。

## 4. 连接真机与基础自检

### 4.1 配置网络

示例：接狗网卡为 `enp3s0`，控制电脑使用 `192.168.123.99`。

```bash
sudo ip addr add 192.168.123.99/24 dev enp3s0
ping -c 2 192.168.123.161
```

注意：

- 不要把控制电脑设成 `192.168.123.161`，这是机器狗默认地址；
- Windows 图形界面中，应给“接狗的那张以太网卡”配置 `192.168.123.x/24`；
- 网关可以留空，不要为了接狗破坏电脑原有外网配置。

### 4.2 加载 DDS 环境

```bash
cd ~/go2_official_ws
GO2_IFACE=enp3s0 source scripts/setup.sh
```

如果 `GO2_IFACE` 写错，常见表现不是明确报错，而是 `ros2 topic list` 卡住或完全没有狗的数据。

### 4.3 检查关键话题

打开两个终端，每个终端都先加载环境：

```bash
ros2 topic hz /lf/sportmodestate
ros2 topic hz /utlidar/cloud_deskewed
```

预期：

| 话题 | 正常频率 |
|---|---:|
| `/lf/sportmodestate` | 约 20 Hz |
| `/utlidar/cloud_deskewed` | L1 约 14 Hz；L2 约 5.5 Hz |
| `/scan`（启动感知后） | 与点云同频，约 14 Hz |

> 以上为本仓库在 Go2 + 机载 L1 上的实测值（2026-10-21）。
> 不同固件/机型会有差异，但**点云与 `/scan` 必须同频**；
> `/scan` 为 0 而点云有频率，先查点云时间戳，见
> [`开发日志.md`](./开发日志.md) 记录 001。

还可以检查：

```bash
ros2 topic list | grep -E 'sportmodestate|lowstate|cloud_deskewed|sport/request'
ros2 topic hz /scan
ros2 topic echo /battery_state --once
```

`/scan` 只有在启动 `mapping.launch.py`、`navigation.launch.py` 或 `patrol.launch.py`
后才会出现。

### 4.4 检查 TF 链

启动导航后执行：

```bash
ros2 run tf2_tools view_frames
```

目标链：

```text
map -> odom -> base_footprint -> base_link -> utlidar_lidar
```

`base_footprint -> base_link` 只允许一个发布者。驱动中的 `tf_chain_guard`
默认 `mode=auto`：

- 机器狗自己发布这段 TF 时，`tf_chain_guard` 不插手；
- 5 秒内无人发布时，它才补链；
- 可通过站点 `site.yaml` 的 `env.GO2_BASE_FOOTPRINT_TF` 设为 `always` 或 `never`。

日志中出现重复 TF 或 Nav2 报多个父节点时，先检查这一段是否被重复发布。

## 5. 建图

### 5.1 启动建图

```bash
cd ~/go2_official_ws
GO2_IFACE=enp3s0 source scripts/setup.sh
ros2 launch go2_patrol_bringup mapping.launch.py
```

该 launch 会启动：

- 机载点云到 `/scan` 的转换；
- `odom_bridge`、`battery_bridge`、`twist_bridge`、`tf_chain_guard`；
- `slam_toolbox`。

`mapping.launch.py` 不自动启动 RViz。需要观察时，另开终端运行：

```bash
source scripts/setup.sh
rviz2
```

至少添加 `Map`、`LaserScan`、`TF`，并把 Fixed Frame 设为 `map`。

### 5.2 遥控走图

用遥控器低速走完整个巡检区域：

- 转弯处减速；
- 不要贴墙；
- 走回起点附近，方便闭环；
- 避免长时间对着玻璃、镜面或大面积反光物；
- L2 只有约 5.5 Hz，速度过快会造成地图重影。

### 5.3 保存地图

```bash
./scripts/save_map.sh office_floor
```

生成：

```text
src/go2_patrol_bringup/maps/office_floor.yaml
src/go2_patrol_bringup/maps/office_floor.pgm
```

地图质量通过标准：

- 墙线连续，没有大面积重影；
- 走回起点时没有明显错层；
- 固定障碍轮廓可辨认；
- 机器人附近没有持续扩大的糊状点。

## 6. 导航单点测试

### 6.1 启动导航

```bash
ros2 launch go2_patrol_bringup navigation.launch.py \
  map:=$HOME/go2_official_ws/src/go2_patrol_bringup/maps/office_floor.yaml
```

默认会启动 RViz 巡检视图。

### 6.2 给初始位姿和目标

在 RViz 中：

1. 选择 `2D Pose Estimate`；
2. 在地图上点出机器狗的实际位置，并拖出实际朝向；
3. 等 AMCL 粒子收敛；
4. 用 `2D Goal Pose` 发一个前方 1～2 米的近目标；
5. 确认全局路径、局部路径、机器狗运动和停车都正常。

第一次测试必须降速。建议先在站点 `site.yaml` 中把 `safety.max_linear` 设为
`0.3` 或 `0.4`，确认安全后再逐步提高。

## 7. 巡检点位、语音和站点资产

### 7.1 采集点位

导航和 AMCL 正常运行后，把机器狗遥控到目标位置：

```bash
ros2 run go2_patrol_patrol record_waypoint equipment_zone
```

该工具默认订阅 `/amcl_pose`，输出的是 **map 帧**坐标，可直接用于 Nav2 目标。
只有显式添加 `--allow-odom-fallback` 且 `/amcl_pose` 一直无数据时，才会退回
`/odom`；此时坐标属于 odom 帧，不能直接当作地图坐标使用。

### 7.2 `waypoints.yaml`

```yaml
waypoints:
  - name: home
    x: 0.0
    y: 0.0
    yaw: 0.0
    dwell: 4.0
    speech: home
    home: true

  - name: equipment_zone
    x: 2.0
    y: 0.0
    yaw: 0.0
    dwell: 4.0
    speech: equipment_zone
    yaw_mode: fixed
```

字段说明：

| 字段 | 说明 |
|---|---|
| `name` | 点位名，也是日志和默认语音 ID |
| `x` / `y` | map 坐标系位置，单位米 |
| `yaw` | 目标朝向，单位弧度 |
| `dwell` | 到点停留秒数 |
| `speech` | 对应 `audio/<speech>.wav`，留空则不播报 |
| `home` | 返航点；建议只设一个 |
| `yaw_mode` | `fixed`、`travel` 或 `next`，覆盖站点默认策略 |

`yaw_mode` 建议：

- `fixed`：必须正对设备拍照、读表时使用；
- `travel`：普通路口，到点后朝进点方向，减少原地转；
- `next`：到点后朝下一段方向，方便直接继续走。

### 7.3 语音

把语音文件放在站点目录：

```text
audio/
├── home.wav
└── equipment_zone.wav
```

先手动验证播放器：

```bash
aplay audio/home.wav
```

没有录音时可在 Windows 离线生成：

```powershell
powershell -ExecutionPolicy Bypass `
  -File deploy/tools/make_voice_wavs.ps1 `
  -OutDir <站点目录>\audio
```

生产机缺少某个 wav 不会中断巡检，只会在日志中记录 `audio not found`。

### 7.4 站点目录

建议每个现场使用一份独立站点目录：

```text
site-office/
├── map.yaml
├── map.pgm
├── waypoints.yaml
├── site.yaml
└── audio/
    ├── home.wav
    └── equipment_zone.wav
```

可从 `deploy/site.example/` 复制模板。

### 7.5 `site.yaml` 关键配置

```yaml
name: office
iface: enp3s0
dog_ip: 192.168.123.161

initial_pose:
  x: 0.0
  y: 0.0
  yaw: 0.0

robot_radius: 0.35
rviz: false

patrol:
  loops: 1
  return_home: true
  battery_low: 20.0
  arrival_tolerance: 0.30
  goal_retry_limit: 3
  goal_retry_delay: 5.0
  on_goal_failure: abort
  yaw_mode: travel

safety:
  max_linear: 0.3
  max_angular: 0.8
  front_half_angle_deg: 30.0
  emergency_distance: 0.20
  stop_distance: 0.35
  slow_distance: 0.60
  cmd_vel_timeout: 0.5

env:
  GO2_BASE_FOOTPRINT_TF: auto
  GO2_REQUIRE_SCAN: "true"
```

规则：

- `initial_pose` 必须填写机器狗每次开机时真实、固定的起点；
- 三个距离必须满足 `emergency_distance < stop_distance < slow_distance`；
- `loops: 0` 表示无限循环，`loops: 1` 表示跑完一圈后停在当前状态；
- 修改 `site.yaml` 后必须重新执行 `apply_site.sh`。

`nav2_params.yaml` 和 `site.env` 是生成文件，不要手工修改。

### 7.6 开发机试跑站点

```bash
deploy/apply_site.sh \
  --site-dir <站点目录> \
  --name office \
  --sites-dir ./sites

GO2_SITES=./sites deploy/run_site.sh office
```

`run_site.sh` 会读取站点参数并启动 Nav2、巡检和语音节点。巡检启动后自动开跑。

### 7.7 直接 launch 和站点启动的区别

| 方式 | 用途 | 注意事项 |
|---|---|---|
| `ros2 launch go2_patrol_bringup patrol.launch.py` | 快速调试 | 使用仓库默认地图、点位和参数，不读取站点生成参数 |
| `deploy/run_site.sh <站点>` | 真实现场 | 使用站点地图、固定初始位姿、安全阈值和语音 |

正式巡检应使用 `run_site.sh`。

### 7.8 巡检服务

```bash
ros2 service call /patrol/pause  std_srvs/srv/Trigger
ros2 service call /patrol/resume std_srvs/srv/Trigger
ros2 service call /patrol/stop   std_srvs/srv/Trigger
ros2 service call /patrol/start  std_srvs/srv/Trigger
```

语义：

- 启动后自动巡检，不需要再发 `/patrol/start`；
- `pause` 暂停，`resume` 从暂停状态继续；
- `stop` 终止本次巡检，节点仍存活但不再动作；
- 本次巡检结束后 `/patrol/start` 不能重新开始，需要重启 launch 或服务；
- 无人值守长期运行时，站点 `loops` 应设为 `0`。

## 8. 生产机安装、自启和升级回滚

### 8.1 在线安装

```bash
git clone https://github.com/xqd922/go2-official-patrol.git /tmp/go2-src
cd /tmp/go2-src
sudo deploy/install.sh --ref v0.1.0 --iface enp3s0
```

安装目录：

```text
/opt/go2/releases/<版本>/       代码与编译产物
/opt/go2/current                 当前版本软链
/opt/go2/sites/<站点>/           站点资产
/etc/go2/site.env                机器级网络配置
```

### 8.2 离线安装

开发机打包：

```bash
deploy/make_release_bundle.sh v0.1.0
sha256sum dist/go2-official-ws-v0.1.0-bundle.tar.gz
```

生产机安装：

```bash
sudo deploy/install.sh \
  --bundle /media/usb/go2-official-ws-v0.1.0-bundle.tar.gz \
  --ref v0.1.0 \
  --no-apt \
  --iface enp3s0
```

离线机必须提前安装 ROS 2 Humble 和 `deploy/apt-deps.txt` 中的依赖。

### 8.3 落地站点并启用服务

```bash
sudo /opt/go2/current/deploy/apply_site.sh \
  --site-dir /media/usb/site-office \
  --name office

sudo /opt/go2/current/deploy/preflight.sh office
sudo systemctl enable --now go2-patrol@office
```

常用运维命令：

```bash
systemctl status go2-patrol@office
journalctl -u go2-patrol@office -f
sudo systemctl restart go2-patrol@office
sudo systemctl stop go2-patrol@office
```

生产机默认不开 RViz。现场调试可临时设置 `GO2_RVIZ=true` 后手动运行
`run_site.sh`。

### 8.4 升级与回滚

```bash
sudo /opt/go2/current/deploy/install.sh --ref v0.2.0
sudo /opt/go2/current/deploy/install.sh --rollback v0.1.0
```

升级只切换 `/opt/go2/current`，站点资产不会被覆盖。升级后应重新执行一次
`apply_site.sh`，用新版本模板重新生成站点 `nav2_params.yaml`。

## 9. 真机安全基线

每次更换机器狗、负载、地面或雷达安装方式后，都要重新验证。

### 9.1 首次速度

- 建议从 `max_linear: 0.3`、`max_angular: 0.8` 开始；
- 确认制动距离、定位稳定性和场地通行宽度后，再逐步提高；
- 不要因为 L2 点云更密就直接高速运行。

### 9.2 必须实测的保护

| 保护 | 测试方法 | 预期 |
|---|---|---|
| 前置减速 | 前方约 0.60 m 放障碍 | 速度降低 |
| 前置停车 | 前方约 0.35 m 放障碍 | 停止并记录 `front safety stop` |
| 前置急停 | 前方约 0.20 m 放障碍 | 立即刹车 |
| 扫描断流 | 停止点云发布或断开雷达数据 | 日志出现 `没有新的 /scan` 并停车 |
| 指令断流 | 行进中结束巡检或导航进程 | 约 0.5 秒内补发 `STOP_MOVE` |
| 人工接管 | 遥控器接管或 `/patrol/stop` | 机器狗停止自动运动 |

软件保护不能替代硬件急停和遥控器。首次运行必须有人跟随并手持遥控器。

## 11. 常见问题

| 现象 | 优先检查 |
|---|---|
| `ros2 topic list` 卡住或没有狗数据 | `GO2_IFACE`、IP、网线、WSL 镜像网络、`CYCLONEDDS_URI` |
| 有点云但没有 `/scan` | TF 链、`base_footprint -> base_link`、`/utlidar/cloud_deskewed` |
| Nav2 启动失败 | 站点 `nav2_params.yaml` 是否由 `apply_site.sh` 正常生成 |
| 定位粒子不收敛 | 初始位姿、地图是否过期、现场是否移动固定起点 |
| 机器狗不走 | `/cmd_vel`、`/scan`、急停状态、狗是否已站立、遥控器是否接管 |
| 到点原地转很久 | 点位 `yaw_mode`，路口优先使用 `travel` |
| 到点没有声音 | wav 文件、`aplay`、站点 `audio_dir`、日志 `audio not found` |
| 服务反复重启 | `journalctl -u go2-patrol@<站点>`，先看 `preflight` 和参数错误 |
| 升级后异常 | 切回旧版本，并重新生成站点参数 |

## 12. 已知限制

- 本方案使用机载 L1/L2、SLAM Toolbox、AMCL 和 Nav2，不使用宇树官方
  `slam_operate` 导航服务；
- 官方 `slam_operate` 需要 EDU、拓展坞和官方外置雷达，不能仅依赖机载 L2；
- 到点语音默认从控制电脑播放，尚未验证从机器狗本体喇叭播放；
- `go2_patrol_reflective` 只做反光条检测测试，不接入 Nav2 costmap；
- 软件前置保护不能替代遥控器、硬件急停和现场安全管理；
- 不同固件的话题名可能变化，现场以 `ros2 topic list` 为准。

### 12.1 机载 L2 与官方 SLAM 服务选型

机身自带的新型雷达是 Unitree 4D LiDAR L2，旧批次可能是 L1。两者 ROS 话题接口相同，
但官方 `slam_operate` 导航服务不使用机载雷达，只支持
EDU + 拓展坞 + 官方外置 MID-360/XT16。

| 硬件配置 | 推荐导航方案 | 反光条能否作为墙并自动绕行 |
|---|---|---|
| EDU 仅有内置 L1/L2 | 本仓库：SLAM Toolbox + AMCL + Nav2 | 有扩展可能，但当前 `go2_patrol_reflective` 尚未接入 costmap |
| EDU + 拓展坞 + 官方 MID-360/XT16 | 官方 `slam_operate` | 不可以，只能做暂停或告警 |
| EDU + 拓展坞 + 外置雷达，坚持自研 Nav2 | 自定义雷达驱动 + Nav2 | 可以，但工程量最大 |

官方服务常见场地限制：

- 建议区域不大于 25 m × 25 m；
- 单个目标点距离不超过 10 m；
- 障碍物高度建议不低于 20 cm；
- `mode=1` 停障；`mode=0` 绕障时通道宽度通常需不小于 0.8 m；
- 官方建议连续使用不超过 30 分钟，避免拓展坞过热降频。

如果只需要巡检和到点语音，且有官方外置雷达，可以评估官方服务；
如果必须让反光条虚拟墙参与避障，当前应继续使用本仓库的 Nav2 路线。
