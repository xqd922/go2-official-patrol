## 0. 先定交付形态（决定要不要多一台电脑）

物料表在形态定了之后才有意义，**别在形态没定前下单**。

| 形态 | "大脑"是谁 | 客户看到 | 物料差异 |
|---|---|---|---|
| **A 全机载** | 拓展坞 PC / 机载算力模组（默认 `192.168.123.18`） | 只有一条狗 | 需要拓展坞 + 算力模组，不需要常驻电脑 |
| **B 外挂常驻电脑**（本项目默认） | 迷你主机 / 工控机，固定在机柜或挂狗背 | 狗 + 一个小盒子 | 需要常驻电脑 + 网线 |
| **C 客户自备电脑** | 客户自己的 Ubuntu 机器 | 狗 + 客户已有的电脑 | 只交付代码包与站点资产 |

**需要向客户说清的一件事：** 机器狗出厂只会站立、行走、听遥控器。认路、规划路线、巡检顺序、语音播报都在"大脑"（那台电脑）上跑。
所以**交付物 = 狗 + 大脑 + 站点资产**；不接大脑时，它就是一只能遥控的普通 Go2。

## 4. 客户现场前置条件（建议提前 48 小时确认）

- [ ] 220V 电源 + 机器狗充电位置
- [ ] 场地清空、地面平整干爽、照明正常（玻璃 / 镜面尽量远离巡检路线）
- [ ] 现场对接人（能拍板、能签字验收）
- [ ] 若走无线：客户 WiFi / 网络权限（或我方提供路由器）
- [ ] 若装常驻电脑：机柜或固定落脚位置
- [ ] 巡检点位清单与业务话术（客户确认文字内容，语音按此生成）

## 5. 交付当天流程（顺序不要跳）

```text
① 装大脑（装代码 + 站点 + systemd 自启）
   → ② preflight 预检 → ③ 定位与单点导航 → ④ 前置急停实测
   → ⑤ 整圈巡检（含每个点位出声）→ ⑥ 拔掉开发机验证独立性
   → ⑦ 断电重启自启 → ⑧ 回滚演练 → ⑨ 客户培训 + 签字交接
```

## 6. 交付验收清单（必须逐条打勾）

> 完整细则见 [`生产交付手册.md`](生产交付手册.md) 第 8 节。

**A. 安装与自启**

- [ ] `sudo deploy/install.sh --ref <版本>` 无错误结束，`ls -l /opt/go2/current` 指向正确版本
- [ ] `sudo /opt/go2/current/deploy/preflight.sh <站点>` 输出无 `[FAIL]`
- [ ] `systemctl is-enabled go2-patrol@<站点>` 为 `enabled`
- [ ] 断电重启后无需人工登录即自动运行：`systemctl is-active go2-patrol@<站点>` 为 `active`
- [ ] **拔掉开发机**（笔记本断网 / 关机）后整圈巡检仍能跑通——确认"大脑"在交付机上

**B. 定位与导航**

- [ ] `ros2 topic echo /amcl_pose --once` 的位姿与固定起点一致（偏差 < 0.3 m）
- [ ] RViz 里 `map` 与 `/scan` 重合、无明显错层
- [ ] 单目标测试：给一个近点 goal，机器狗到点并停下（在 `arrival_tolerance` 内）

**C. 巡检业务**

- [ ] `/patrol/start` 后按 `waypoints.yaml` 顺序巡航，全部到点、停留时间正确
- [ ] 每个点位的 `speech` 都有对应 wav，且**现场实际出声**
- [ ] 行进中播报正常（转弯提醒不卡顿、不是停下才念）
- [ ] 低电量保护：把阈值临时调到当前电量以上，验证返航行为
- [ ] 前置急停：前方 0.35 m 放障碍物，日志出现 `front safety stop` 且机器狗停住

**D. 异常恢复**

- [ ] `sudo kill -9` 主进程后 10 秒内自动重启并重新 `active`
- [ ] 拔掉机器狗网线再插回，任务能恢复（或服务重启后恢复）
- [ ] 把站点 `map.yaml` 改名后重启服务，`preflight.sh` 拒绝启动并留下明确日志

**E. 培训与交接**

- [ ] 教会客户三件事：开机、暂停 / 急停、异常找谁
- [ ] 交接资料齐全（本文第 2 节全部打勾）
- [ ] 双方签字（本文第 7 节）
