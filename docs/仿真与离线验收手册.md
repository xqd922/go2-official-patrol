# Go2 巡检系统：仿真与离线验收手册

> 本文中的“仿真”指仓库自带的**离线闭环演示**：使用假 Go2 话题、生成地图和假语音，
> 跑通与生产相同的 `apply_site.sh -> run_site.sh -> patrol.launch.py` 链路。
>
> 它不是 Gazebo、Isaac Sim 或物理仿真，不模拟轮胎打滑、真实雷达噪声、DDS 网卡和急停距离。

## 1. 这套仿真能验证什么

离线闭环可以验证：

- ROS 2 工作空间和所有节点能否正常启动；
- `/lf/sportmodestate`、`/utlidar/cloud_deskewed` 到 `/scan`、`/odom` 的数据链路；
- SLAM/Nav2 参数是否可加载；
- 站点资产是否完整；
- 航点顺序、圈数、低电量返航和收工返航状态机；
- 到点精度、累计行程和逐点语音是否正常；
- `apply_site.sh`、`render_site.py`、`run_site.sh` 是否仍然可用。

它不能验证：

- 真机网卡、CycloneDDS 组播和官方固件兼容性；
- 机器狗自身是否发布 `base_footprint -> base_link`；
- 实际轮胎打滑、地面材质、负载和制动距离；
- 真实 L1/L2 点云噪声、玻璃反射和地图质量；
- 真机遥控器接管与硬件急停。

因此推荐流程是：**先跑离线验收，再接真机做现场验收**。

## 2. 环境要求

| 项目 | 要求 |
|---|---|
| 系统 | Ubuntu 22.04，或 Windows 11 + WSL2 |
| ROS | ROS 2 Humble |
| 依赖 | `deploy/apt-deps.txt` |
| 工作空间 | 已执行 `scripts/bootstrap.sh`，存在 `install/setup.bash` |
| 显示 | 无头验收不需要显示器；`--rviz` 需要可用图形环境 |

如果环境尚未安装，先按 `docs/真机部署与使用手册.md` 第 3 节完成安装。

每个新终端加载环境：

```bash
cd ~/go2_official_ws
source scripts/setup.sh
```

离线演示不需要接机器狗，也不要指定真实 `GO2_IFACE`。

## 3. 两种演示不要混淆

| 脚本 | 用途 | 是否有自动验收 |
|---|---|---|
| `tools/offline_demo/run_patrol_demo.sh` | 巡检全链路闭环验收 | 有，失败返回非 0 |
| `tools/offline_demo/run_demo.sh` | 只演示假狗和 SLAM 建图 | 无，仅肉眼观察 |

日常回归和交付门槛应使用 `run_patrol_demo.sh`。

## 4. 运行一次完整闭环验收

```bash
cd ~/go2_official_ws
tools/offline_demo/run_patrol_demo.sh
```

默认约 2 分钟，成功后退出码为 0，并打印类似：

```text
================ 离线闭环演示结果 ================
预期点位 : home -> zone_ne -> zone_se -> zone_sw -> zone_nw -> equipment_zone -> home
实际到达 : home -> zone_ne -> zone_se -> zone_sw -> zone_nw -> equipment_zone -> home
播报记录 : home, zone_ne, zone_se, zone_sw, zone_nw, equipment_zone
  [ OK ] 目标序列全部到达
  [ OK ] 累计行程 ≥ 5m
  [ OK ] 每个点位的播报都出现过
  [ OK ] fixed 点位到点朝向误差 ≤ 0.35rad
结论     : 通过（全部目标点到达）
[demo] 验收通过 ✅
```

报告默认写入：

```text
/tmp/go2_offline_demo/report.json
```

日志默认写入：

```text
/tmp/go2_offline_demo/
├── fake_go2.log
├── patrol_stack.log
├── report.json
└── pids
```

## 5. 脚本实际做了什么

`run_patrol_demo.sh` 按以下顺序执行：

1. `make_demo_map.py` 生成地图；
2. `make_demo_audio.py` 生成语音占位文件；
3. `check_site.py` 校验站点资产；
4. `deploy/apply_site.sh` 落地站点并生成 `nav2_params.yaml` / `site.env`；
5. `fake_go2_loop.py` 启动闭环假狗；
6. `deploy/run_site.sh` 启动与生产相同的巡检栈；
7. `demo_verify.py` 逐点验收顺序、精度、行程和播报。

关键点：离线演示不是另写一套导航逻辑，而是复用生产链路的站点落地和启动脚本。

## 6. 常用场景

### 6.1 带 RViz 持续观察

```bash
tools/offline_demo/run_patrol_demo.sh --rviz --loops 0 --keep
```

结束后清理：

```bash
tools/offline_demo/run_patrol_demo.sh --clean
```

RViz 中重点观察：

| 显示项 | 话题 | 用途 |
|---|---|---|
| Map | `/map` | 静态地图 |
| LaserScan | `/scan` | 感知输出 |
| GlobalPlan / LocalPlan | `/plan`、`/local_plan` | 规划与控制 |
| AMCLPose / ParticleCloud | `/amcl_pose`、`/particle_cloud` | 定位收敛 |
| WaypointMarkers | `/waypoints/markers` | 巡检点状态 |

点位球颜色：

- 蓝色：本圈未访问；
- 黄色：当前目标；
- 绿色：已经到达；
- 红色：返航点。

### 6.2 低电量返航

```bash
tools/offline_demo/run_patrol_demo.sh --battery-drop-after 60
```

运行 60 秒后把假电量降到 15%，验证巡检中止和返航。

### 6.3 动态障碍

```bash
tools/offline_demo/run_patrol_demo.sh \
  --obstacles "0.5,0,0.6,0.6,0.6"
```

格式为 `x,y[,sx[,sy[,height]]]`，多个障碍用分号分隔。

### 6.4 多圈和更长超时

```bash
tools/offline_demo/run_patrol_demo.sh --loops 3 --timeout 900
```

### 6.5 不返航

```bash
tools/offline_demo/run_patrol_demo.sh --no-return-home
```

### 6.6 复用上次站点

```bash
tools/offline_demo/run_patrol_demo.sh --no-apply
```

只适合调整参数或反复验证；修改了站点资产后不要跳过 `apply_site.sh`。

全部选项：

```bash
tools/offline_demo/run_patrol_demo.sh --help
```

## 7. 验收判据

默认验收由 `demo_verify.py` 完成：

| 判据 | 阈值 |
|---|---|
| 到点顺序 | 与 `waypoints.yaml` 一致 |
| 到点精度 | AMCL 位姿与目标点误差不超过 0.40 m |
| 累计行程 | 至少 5 m |
| 逐点播报 | 每个点位的 speech ID 都出现 |
| 到点朝向 | `fixed` 点位误差不超过 0.35 rad；`travel`/`next` 不判朝向 |

退出码：

- `0`：验收通过；
- 非 `0`：验收失败，应查看 `patrol_stack.log` 和 `report.json`。

## 8. RViz 配置和显示

巡检主视图：

```text
src/go2_patrol_bringup/rviz/patrol.rviz
```

建图演示视图：

```text
tools/offline_demo/demo.rviz
```

常见显示问题：

- `/scan` 是 best effort QoS，订阅端也必须使用 sensor data/best effort；
- Fixed Frame 通常设为 `map`；
- 无显示器环境不要使用 `--rviz`；
- 远程桌面叠加 WSLg 时，PointCloud2 全帧显示可能明显卡顿，可先关闭点云显示。

## 10. 常见问题

| 现象 | 原因与处理 |
|---|---|
| `ros2: command not found` | 先执行 `source scripts/setup.sh` |
| 提示工作空间未编译 | 执行 `scripts/bootstrap.sh` 或 `colcon build --symlink-install` |
| 上次进程残留 | `tools/offline_demo/run_patrol_demo.sh --clean` |
| 没有 `/scan` | 假狗未启动、TF 链断开或点云转换失败，先看 `patrol_stack.log` |
| Nav2 一直不启动 | 参数 YAML 有误或 `/scan`、TF 不完整 |
| 巡检不开始 | 查看 `patrol_manager` 日志和 `waypoints.yaml` |
| 某个点反复失败 | 检查点位是否落墙里、地图是否生成正确、`check_site.py` 是否报告净空不足 |
| 到点没有播报 | 检查 `audio/<speech>.wav` 和 `voice_player` 日志 |
| 验收超时 | 增加 `--timeout`，并检查机器性能；超时本身仍说明链路没有按预期完成 |
| RViz 打不开 | 确认有图形环境，先不带 `--rviz` 跑无头验收 |
| 无头能过，真机失败 | 正常现象，离线测不到 DDS、真实 TF、急停距离和定位质量，转真机手册排查 |

## 11. 建图演示 `run_demo.sh`

只观察假狗和 SLAM 建图时：

```bash
tools/offline_demo/run_demo.sh start
tools/offline_demo/run_demo.sh stop
```

注意：

- 脚本默认工作空间是 `$HOME/go2_official_ws`；
- 它额外启动 `base_footprint -> base_link` 静态 TF；
- 它没有自动验收，不能替代 `run_patrol_demo.sh`；
- 真机上不要照搬这条静态 TF，除非已确认机器狗自身不发布该变换。

## 12. 离线演示的边界

以下内容必须到真机验证：

- `GO2_IFACE` 和 CycloneDDS 网络；
- 官方 Unitree 消息和固件兼容性；
- 真实雷达点云频率、字段和噪声；
- 机器狗是否发布 `base_footprint -> base_link`；
- 真实制动距离和前置急停阈值；
- Nav2 在真实地面、负载和障碍下的运动效果；
- 系统开机自启、断电恢复和远程运维。

离线验收通过只表示“软件链路自洽”，不表示“现场可以无人值守运行”。

## 13. 历史环境问题摘要

以下问题在早期环境搭建和离线调试中已经处理过，复现环境时仍可能遇到：

| 问题 | 处理 |
|---|---|
| `ros-humble-desktop` 找不到 | 先添加 ROS 2 apt 源和密钥，再 `apt update` |
| WSL2 默认 NAT 连不上机器狗 | `.wslconfig` 设置 `networkingMode=mirrored`、`firewall=false`，然后 `wsl --shutdown` |
| 编译官方示例包时 OOM | 给 WSL 增加内存；无关示例可加 `COLCON_IGNORE`，或降低 `MAKEFLAGS` 并行度 |
| `source install/setup.bash` 报残留包不存在 | 清理 `build/ install/ log/` 后全量重编 |
| WSLg 中 RViz 窗口登记但不显示 | `wsl --shutdown` 后重新进入 WSL |
| 远程桌面下 RViz 卡顿 | 缩小窗口、关闭 PointCloud2、降低点云频率，优先截图确认 |
| shell 脚本在 Linux 报 `bash\r` | 确保 Git 使用 LF，仓库 `.gitattributes` 已约束 `.sh` |
| `setup.sh` 默认网卡不匹配 | 用 `GO2_IFACE=<实际网卡> source scripts/setup.sh` 显式覆盖 |

更完整的旧版环境过程记录已归档到 `docs/_archive/2026-10-20/`。
