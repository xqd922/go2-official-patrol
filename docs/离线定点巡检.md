# 离线定点巡检（无需 Go2 实机）

在没有机器狗的情况下，用模拟数据跑通 Nav2 定位导航与航点巡检闭环。

## 一、链路

```text
fake_go2（离线替身）
   ├── 发布 /lf/sportmodestate  ← 由 /cmd_vel 积分出的位姿
   ├── 发布 /lf/lowstate（电量 87%）
   ├── 发布 /utlidar/cloud_deskewed（房间点云）
   └── 订阅 /cmd_vel → 二维运动学积分 → 更新 x/y/yaw

odom_bridge → /odom + TF(odom→base_footprint)
pointcloud_to_laserscan → /scan
Nav2（AMCL + 规划/控制）→ /cmd_vel → 回到 fake_go2
patrol_manager → /robot/say → voice_player
```

闭环：Nav2 → `/cmd_vel` → fake_go2 → 模拟位姿 → `/odom` + TF → Nav2。

## 二、一条命令启动

```bash
cd <仓库根>
tools/offline_demo/run_demo.sh patrol
```

默认使用 `<仓库根>/src/go2_patrol_bringup/maps/map.yaml`；
也可显式指定地图：

```bash
tools/offline_demo/run_demo.sh patrol /path/to/map.yaml
```

等约 40 秒（Nav2 激活 + AMCL 收敛），日志出现
`Nav2 is ready for use!` 后启动巡检：

```bash
ros2 service call /patrol/start std_srvs/srv/Trigger
```

停止：

```bash
tools/offline_demo/run_demo.sh stop
```

## 三、先建图（首次使用）

```bash
tools/offline_demo/run_demo.sh start      # 建图 + RViz
./scripts/save_map.sh map                 # 存成 src/go2_patrol_bringup/maps/map.yaml
tools/offline_demo/run_demo.sh stop
```

`save_map.sh` 走 nav2 的 `map_saver_cli`，显式指定输出路径，
不依赖运行目录；`maps/` 通过 symlink-install 与 `install/share/.../maps` 共享同一份文件。

## 四、安全隔离（重要）

离线链路通过 `offline_patrol.launch.py` 启动，其中 `driver` 以
`sport_output:=false` 运行：`twist_bridge` **不订阅 `/cmd_vel`，也不创建
`/api/sport/request` 发布者**。因此即使控制电脑同时连着真机，离线演示也不会
向 Go2 发送任何运动命令。

真机链路继续使用 `patrol.launch.py`，其行为未做任何改变
（`sport_output` 默认 `true`）。

## 五、RViz 能看到什么

`tools/offline_demo/demo.rviz`：

- Map（占据栅格）
- LaserScan_2D（`/scan`）
- PointCloud2_RAW（原始三维点云，默认关闭以减少远程桌面压力）
- TF、Odometry（机器人当前位置与朝向）
- Nav2 Plan（`/plan` 规划路径）
- Nav2 Goal（`/goal_pose` 导航目标）
- AMCL Particles（粒子云，默认关闭）

## 六、当前限制

- 这是二维运动学近似，不含足式动力学、摩擦、打滑与真实加减速特性；
- 点云用射线模型理想生成，不模拟噪声、反射与遮挡；
- 语音只有 `[VOICE] xxx` 日志，因为 `audio/` 下没有对应 wav；
- 以上全部只能证明软件链路闭环，真机行为必须现场验收。
