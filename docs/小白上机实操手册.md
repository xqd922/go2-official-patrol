# Go2 巡检系统 · 小白上机实操手册

> 这份文档写给**完全没接触过 ROS、第一次接真机器狗**的人。
> 每一步都写清：**敲什么命令 → 应该看到什么 → 看不到怎么办**。
> 命令可以直接复制粘贴；所有命令都假设"当前目录是工程根目录"。

---

## 0. 先花 3 分钟搞懂：这套东西怎么工作

一句话：**狗负责走和看，电脑负责想，网线是它们之间的嘴和耳朵。**

| 角色 | 是什么 | 我们的代码放在哪 |
|---|---|---|
| 机器狗 Go2 | 会走路的本体 + 机载雷达 | ❌ **不放代码**（狗里是宇树自己的系统，我们不碰） |
| 控制电脑 | 笔记本 / 工控机（就是你现在的 Windows + WSL） | ✅ **代码全在这台电脑上跑** |
| 网线 | 电脑和狗之间的数据通道 | —— |

数据是怎么流动的（从左到右）：

```text
雷达点云 → 变成 2D 激光 → SLAM 建地图/定位 → Nav2 规划路线 → 速度指令 → 狗走
                                                    ↓
                                       到点/转弯 → 电脑喇叭播报语音
```

**三个新手最容易搞错的点：**

1. **代码不传进狗里。** 狗只接收"往前走/转弯"这种指令，接收雷达数据回传。所以你"部署代码"其实是"把工程放到那台接狗的电脑上"。
2. **语音从控制电脑的喇叭出**，不是狗身上的喇叭（狗自带喇叭要另走宇树 SDK，不在本项目范围）。
3. **没有狗也能先跑**。仓库自带假机器狗演示，软件链路能 100% 跑通之后，接真机只是换数据来源，风险小很多。

## 0.5 交付到底交什么？（新手最容易想错的一件事）

很多人的第一反应是：

> "我把程序装进狗里，狗就变成会巡检的机器人了，客户插上电就能用。"

**其实不是。这套系统交付的是「一条狗 + 一台电脑」两件东西，缺一不可。**

打个比方：

| 比作 | 现实里是什么 | 谁给的 |
|---|---|---|
| 身体、腿、眼睛 | 机器狗 Go2（机载激光雷达就是眼睛） | 宇树出厂自带 |
| **大脑 / 司机** | **那台跑我们代码的电脑**（小工控机或笔记本） | **交付时一起给** |
| 神经（雷达数据往上、控制指令往下） | 一根网线 | 一起给 |

所以"交付完直接就能用"这句话是对的，但它有个前提：**交付的时候，那台电脑也已经装好、配好、开机自启了。**
客户看到的是"插电 → 开机 → 狗自己去巡检"；看不到的，是旁边那台一直在跑程序的电脑。

### 为什么不能把程序直接装进狗肚子里？

| 原因 | 说人话 |
|---|---|
| 机载系统归宇树管 | 里面的软件宇树自己维护，第三方程序长期塞进去没有官方支持 |
| 固件升级会覆盖 | 狗一升级固件，我们塞进去的东西可能就没了，白干 |
| 算力 / 存储不够 | SLAM + Nav2 + 可视化是一整套，机载那点算力跑起来又慢又卡 |
| ROS 2 环境对不上 | 我们依赖 ROS 2 Humble + Nav2，机载系统不一定同版本，装不上或装上就跑崩 |
| 出事责任分不清 | 刷坏了要返厂，谁的责任说不清，售后很痛 |

> Go2 EDU 版**理论上**可以 SSH 进机载电脑（一般是 `192.168.123.18`，以实机为准）装东西，
> 但"装上能跑"和"能稳定交付给客户"是两码事。本项目选"程序跑外接电脑"，图的就是稳、能升级、能回滚。

### 三种交付形态，成本差很多，先选一种

| 形态 | 客户拿到手 | 好处 | 代价 |
|---|---|---|---|
| **A. 狗 + 配套电脑（本项目默认）** | 狗 + 一台小工控机（固定在场地机柜/墙边，或放狗背包里）+ 网线 | 最稳、好维护、升级和回滚都是一条命令 | 客户多一台设备、多一份电费 |
| **B. 狗 + 客户自己的电脑** | 狗 + 我们的安装包，客户在自家 Ubuntu 电脑上装 | 省一台机器 | 客户电脑的系统版本、网卡得对得上，出问题先查他的机器 |
| **C. 程序装进狗机载电脑** | 看起来只有一条狗 | 看起来最"干净" | 风险最高、会被固件覆盖，本项目**没有**走这条路 |

**要让客户真的"只拿到一条狗"，目前唯一成熟办法是买宇树官方的 SLAM 导航服务
（EDU + 官方外置 MID-360/XT16 雷达）**，它的限制见
[`EDU与L2-官方SLAM导航服务对比.md`](EDU与L2-官方SLAM导航服务对比.md)。

### 交付时客户实际会收到什么？（一张清单）

| 类别 | 内容 | 谁准备 |
|---|---|---|
| 硬件 | 机器狗（电池、遥控器、充电器）、网线 | 客户/宇树 |
| 硬件 | 小电脑（工控机或笔记本），**已装好系统、代码、开机自启** | 我们 |
| 软件 | `/opt/go2/releases/<版本>` + `current` 软链（出问题能回滚） | 我们，用 `deploy/install.sh` 装 |
| 站点资产 | 地图、巡检点位、语音、`site.yaml` 参数 | 我们现场标定 |
| 说明 | 一页纸《开机即用说明》：怎么开机、怎么暂停、坏了找谁 | 我们 |

给客户培训只用教三件事：**开机、急停/暂停、打不开找谁**。
其余运维（改点位、换地图、升级版本）都留给我们。

## 1. 名词大白话对照表

碰到不认识的词，回来查这张表就行。

| 名词 | 大白话 |
|---|---|
| **ROS 2** | 机器人圈的"通信标准 + 工具箱"，一堆小程序靠它互相传消息 |
| **节点 (node)** | 一个独立小程序。比如"读雷达的""算路线的""说话的"各是一个节点 |
| **话题 (topic)** | 节点之间传消息的"频道"。`/scan` 就是激光数据的频道 |
| **消息 (message)** | 频道里传的内容 |
| **TF** | 坐标系之间的换算关系（地图坐标 ↔ 车身 ↔ 雷达） |
| **DDS** | ROS 2 底下的通信管道。**换电脑/换网卡最容易在这里出问题** |
| **SLAM** | 一边走一边把环境画成地图 |
| **AMCL** | 拿着已有地图 + 当前激光，算出"我现在在地图上的哪儿" |
| **Nav2** | 导航大脑：规划路线、避障、走到目标点 |
| **RViz** | 可视化窗口，看地图、激光、路线、定位在哪 |
| **launch** | 一条命令启动一大串节点的脚本 |
| **工作空间 / 包** | ROS 2 代码的组织单位，我们的仓库叫 `go2_official_ws` |
| **编译 (colcon build)** | 把源码加工成电脑能跑的程序（第一次要几分钟） |
| **source** | 告诉终端"去哪找这些程序"。**每开一个新终端都要做一次** |
| **位姿 (pose)** | 位置 + 朝向（x, y, 朝哪个方向） |

## 3. 第一步：先在电脑上把软件跑通（**不接狗**）

先证明"软件没问题"，再去碰真狗。这一步不需要机器狗。

```bash
# Windows 里打开 WSL 终端后
cd ~/go2_official_ws
tools/offline_demo/run_patrol_demo.sh
```

**应该看到**（约 2 分钟后）：

```text
================ 离线闭环演示结果 ================
实际到达 : home -> zone_ne -> zone_se -> zone_sw -> zone_nw -> equipment_zone -> home
  [ OK ] 目标序列全部到达
  [ OK ] 累计行程 ≥ 5m
  [ OK ] 每个点位的播报都出现过
  [ OK ] fixed 点位到点朝向误差 ≤ 0.35rad
结论     : 通过（全部目标点到达）
[demo] 验收通过 ✅
```

**看不到怎么办：**

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `Permission denied` | 脚本没有可执行权限 | `bash tools/offline_demo/run_patrol_demo.sh`（用 bash 显式调用） |
| `command not found: ros2` | 没加载环境 | 先跑 `source scripts/setup.sh` |
| 卡住不动 / 超时 | 上一次的进程没清干净 | `tools/offline_demo/run_patrol_demo.sh --clean` 再重跑 |
| 想连着看界面 | 演示脚本本身就带 RViz | `tools/offline_demo/run_patrol_demo.sh --rviz --loops 0 --keep` |

## 4. 第二步：把代码搬到"接狗的那台电脑"上

先想清楚：**你要在哪台电脑上接狗？** 按情况选一种方式。

### 情况 A：就用你现在这台电脑（最简单）

**什么都不用传。** 狗就插在这台的网卡上，代码已经在 `~/go2_official_ws`。跳到第 5 步。

### 情况 B：另一台 Linux 电脑（同一个局域网）

1. 在**目标电脑**上看它自己的 IP：

```bash
hostname -I          # 例如输出 192.168.1.50
```

2. 在**现在这台开发机**上把整个工程传过去（排除编译产物，体积小很多）：

```bash
rsync -av --exclude build --exclude install --exclude log \
  ~/go2_official_ws/ 用户名@192.168.1.50:~/go2_official_ws/
```

> 没有 `rsync` 就用 `scp -r`（慢一点、但能用）：
> `scp -r ~/go2_official_ws 用户名@192.168.1.50:~/`

3. 到**目标电脑**上编译并加载环境（**这步不能省**，源码传过去还是源码）：

```bash
cd ~/go2_official_ws
./scripts/bootstrap.sh      # 第一次：装系统依赖 + 拉官方 unitree_ros2 + 编译
source scripts/setup.sh     # 每次开新终端都要
```

### 情况 C：现场没网（用 U 盘交付，最省事）

1. 在**开发机**上打包：

```bash
cd ~/go2_official_ws
deploy/make_release_bundle.sh
# 会生成一个 go2-official-ws-<版本>-bundle.tar.gz（内含官方 unitree_ros2 源码）
```

2. 把 tar.gz 拷进 U 盘（Linux 里插 U 盘一般挂在 `/media/<用户名>/<U盘名>`）：

```bash
cp go2-official-ws-*-bundle.tar.gz /media/$USER/*/
```

3. 到**目标电脑**上插 U 盘，一条命令装好（含编译）：

```bash
sudo deploy/install.sh --bundle /media/$USER/<U盘名>/go2-official-ws-v0.1.0-bundle.tar.gz \
     --ref v0.1.0 --no-apt --iface <接狗的网卡名>
```

### 情况 D：目标电脑能上网（最推荐给长期项目）

```bash
git clone https://github.com/xqd922/go2-official-patrol.git go2_official_ws
cd go2_official_ws
sudo deploy/install.sh --iface <接狗的网卡名>
```

`install.sh` 会把代码装到 `/opt/go2/releases/<版本>`，并用 `current` 软链指向当前版本——
以后升级只切软链，出问题一条命令回滚。

### 传完必须知道的两件事

1. **改了代码要重新编译**：`colcon build`（只编某个包更快：`colcon build --packages-select go2_patrol_patrol`）。
2. **每开一个新终端都要 `source scripts/setup.sh`**，否则会报"找不到包/找不到话题"。

## 5. 第三步：电脑连狗（连线 + 网络）

### 5.1 插线

网线一头插机器狗（机身侧面/背部网口），一头插电脑网口。狗开机（侧躺时扳起、站起后进入正常状态）。

### 5.2 确认电脑认到哪张网卡

```bash
ip link
```

找出状态是 `UP` 的那张有线网卡，名字可能长这样：`enp3s0`、`eno1`、`eth0`。

> 看不懂就用排除法：`ip -brief addr` 看哪张网卡有 `192.168.123.x` 地址，那张就是接狗的。

### 5.3 让电脑和狗在同一网段

机器狗的地址固定是 **`192.168.123.161`**，所以电脑要有一个 `192.168.123.x` 的地址。

**Ubuntu（命令行）：**

```bash
sudo ip addr add 192.168.123.99/24 dev <你的网卡名>
```

**Windows（图形界面，用 WSL 时在 Windows 侧设置）：**

1. 设置 → 网络和 Internet → 高级网络设置 → 更多网络适配器选项；
2. 右键"以太网"（接狗那张）→ 属性 → 双击"Internet 协议版本 4 (TCP/IPv4)"；
3. 选"使用下面的 IP 地址"：IP `192.168.123.99`，子网掩码 `255.255.255.0`，网关留空；
4. 确定。

### 5.4 测试能不能通

```bash
ping 192.168.123.161
```

- 有回包（`time=xx ms`）→ 网络通了，继续。
- `Destination Host Unreachable` → 网线没插好 / 网卡名选错 / IP 没设对 / 狗没开机，回头检查 5.2~5.3。

### 5.5 告诉 ROS 用哪张网卡（关键！）

电脑可能同时有 WiFi、有线、虚拟网卡，ROS 底下的 DDS **必须指定接狗那张**，否则数据传不过来：

```bash
cd ~/go2_official_ws
GO2_IFACE=enp3s0 source scripts/setup.sh      # 换成你自己的网卡名
```

**应该看到**类似输出：

```text
[go2_env] WS=/home/seven/go2_official_ws SITES=.../sites IFACE=enp3s0 DOG=192.168.123.161
```

### 5.6 WSL 用户特别注意

WSL 默认是 NAT 网络，**根本到不了局域网，连不上狗**。需要在 Windows 的 `C:\Users\<你>\.wslconfig` 里加：

```ini
[wsl2]
networkingMode=mirrored
firewall=false
```

然后 PowerShell 里 `wsl --shutdown`（等 8 秒）再进 WSL 生效。
（你这台机器**已经配好了**，所以离线演示里显示的网卡是 `eth1`。）

## 6. 第四步：自检——确认狗的数据真的进来了

**每开一个新终端：**

```bash
cd ~/go2_official_ws
GO2_IFACE=enp3s0 source scripts/setup.sh
```

然后开两个终端分别看两个关键数据：

```bash
# 终端 1：运动状态（狗的心跳）
ros2 topic hz /lf/sportmodestate
# 正常：average rate: 50 左右

# 终端 2：机载雷达点云（狗的眼睛）
ros2 topic hz /utlidar/cloud_deskewed
# 正常：L1 约 11Hz，L2 约 5.5Hz
```

**两个都有频率 = 通信完全正常**，可以开始建图。

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 两个都卡着不出数 | 网卡选错 / 狗没开机 / IP 不通 | 回到第 5 步，先 `ping` 通再说 |
| 只有点云，没有运动状态 | 狗的运控服务没起 | 用官方 App 或遥控器让狗进入正常站立状态 |
| 报 `incompatible QoS` | 订阅端和发布端 QoS 不匹配 | 本项目已修；若是自己写的节点，改成 sensor QoS |
| `ros2 topic list` 直接卡住 | 本机网络/DDS 环境冲突 | `GO2_IFACE` 指定正确网卡；关掉其它 ROS 发行版/域的环境变量 |

## 7. 第五步：建地图（SLAM）

**目的**：让狗走一圈，把环境画成 2D 地图存下来，之后导航就靠这张图。

### 7.1 启动建图

```bash
ros2 launch go2_patrol_bringup mapping.launch.py
```

这条命令会启动：雷达点云 → `/scan` 转换、宇树驱动桥、SLAM 建图节点。

### 7.2 打开可视化看地图长出来（另开一个终端）

```bash
source scripts/setup.sh
rviz2
```

在 RViz 里点左下角 **Add**，添加两个显示项：

- `Map` → Topic 选 `/map`（地图）
- `LaserScan` → Topic 选 `/scan`（当前激光打到的东西）

另外把 **Fixed Frame** 改成 `map`（在左侧 Global Options 里）。

### 7.3 用遥控器慢速走一圈

- 拿遥控器让狗**慢速**沿着要巡检的区域走一圈，最后**回到起点**（回到起点才能闭环，地图才不歪）；
- 走的时候眼睛看 RViz：地图应该一点点"长出来"，墙线应该是连续的；
- **别走太快**：L2 雷达只有 5.5Hz，太快地图会糊；
- 别贴着玻璃/镜面走（会产生假墙）。

### 7.4 存地图

走完停下后：

```bash
./scripts/save_map.sh office_floor
```

**应该看到**保存成功，并在 `src/go2_patrol_bringup/maps/` 下生成 `office_floor.pgm` 和 `office_floor.yaml`。

### 7.5 地图好坏怎么判断

| 好地图 | 坏地图（要重画） |
|---|---|
| 墙线连续、粗细均匀 | 墙有多层重影、糊成一片 |
| 起点闭环正常，没有明显错位 | 走回起点时地图"啪"地跳一下错位 |
| 障碍物（箱子/柱子）轮廓清楚 | 障碍物周围一大团糊点 |

## 8. 第六步：单点导航测试（**最重要的一步，上真机就靠它**）

### 8.1 启动导航

```bash
ros2 launch go2_patrol_bringup navigation.launch.py \
  map:=/home/<用户名>/go2_official_ws/src/go2_patrol_bringup/maps/office_floor.yaml
```

这条命令会打开 RViz 巡检视图（地图、代价地图、激光、路径、定位一屏看完）。

### 8.2 告诉机器人"你现在在哪"（给初始位姿）

1. 在 RViz 工具栏点 **`2D Pose Estimate`**；
2. 在地图上**狗实际站的位置**按住鼠标往**狗头朝的方向**拖一条短线，松手；
3. 看红色的粒子云（`ParticleCloud`）：一开始散得很开，慢慢**聚成一团贴在狗身上**＝定位收敛了。

> 粒子一直乱飞说明位置给错了，或者地图和现场对不上，重新给一次。

### 8.3 发一个近处目标试走

1. 点 **`2D Goal Pose`**，在狗前方 **1~2 米**的空地上点一下、拖出朝向，松手；
2. 看 RViz：出现一条绿色全局路径（`/plan`），然后是蓝色局部路径（`/local_plan`）；
3. 看狗：应该朝目标走，到了停住。

### 8.4 第一次务必做的安全确认

| 检查项 | 怎么做 | 期望 |
|---|---|---|
| 速度够慢吗 | 启动前把限速降到 0.3~0.4 m/s | 狗走起来是"散步"速度 |
| 急停灵不灵 | 人站 1.5m 外，狗朝硬纸箱走 | 前方 0.6m 减速、0.35m 停、0.20m 急停 |
| 遥控器能接管吗 | 手放遥控器上，随时按停 | 一按键狗就停 |
| 定位准不准 | 看 `/amcl_pose` 和激光是否贴合地图墙线 | 激光线和地图墙线基本重合 |

**过了这一关，才允许试巡检。**

## 9. 第七步：配置巡检点和语音

### 9.1 采集巡检点

把狗**遥控**到第一个要巡检的位置，**把朝向调到你希望它到点时朝的方向**，然后：

```bash
source scripts/setup.sh
ros2 run go2_patrol_patrol record_waypoint zone_ne
```

终端会打印一段可以直接贴进 `waypoints.yaml` 的 YAML（含 x / y / yaw）。重复这个动作采完所有点。

> 注意：一定要用**定位收敛后**的地图坐标，别用 odom 漂移值。

### 9.2 一个站点需要哪些文件

照 `deploy/site.example/` 抄一份，改内容即可：

```text
我的站点/
├── map.pgm / map.yaml      # 第 7 步建好的地图（拷过来改名）
├── waypoints.yaml          # 巡检点位（第 9.1 步采的）
├── site.yaml               # 现场参数：初始位姿 / 网卡 / 速度 / 巡检设置
├── voice_lines.json        # 语音话术（可选，用它生成 wav）
└── audio/*.wav             # 到点语音，文件名 = waypoints 里的 speech 字段
```

### 9.3 到点朝向怎么设（**新手最常踩的坑**）

`waypoints.yaml` 里每个点的 `yaw` 是"到点时狗要朝哪"。如果这个朝向和它行进方向差很多，
机器人到点后会**先原地转半天**才继续走。所以：

| 点位类型 | 推荐写法 | 效果 |
|---|---|---|
| 路口、过道拐角 | 站点 `site.yaml` 里写 `yaw_mode: travel` | 到点朝进点方向，不用白转 |
| 要正对设备拍照/读表的点 | 该点写 `yaw_mode: fixed`，并设好 `yaw` | 老实转到指定朝向 |
| 想一起步就走直 | 该点写 `yaw_mode: next` | 到点就朝下一段方向 |

> 实测：路口全部改 `travel` 后，整圈从 85.0s 降到 80.5s，原地转从 1154° 降到 690°。

### 9.4 语音

**方式一（推荐，离线生成）：** 在 Windows 上改 `deploy/site.example/voice_lines.json` 里的话术，然后：

```powershell
powershell -ExecutionPolicy Bypass -File deploy/tools/make_voice_wavs.ps1 -OutDir <你的站点目录>\audio
```

**方式二（自己录音）：** 用手机/电脑录好，命名成 `<speech_id>.wav` 放进 `audio/`，
格式建议 16bit、单声道、22050Hz 或 44100Hz 的 WAV。

**先验证能出声**（Ubuntu 上）：

```bash
aplay <站点目录>/audio/home.wav
```

### 9.5 落地站点并试跑巡检

```bash
# 开发机（站点放在工程内的 sites/ 目录，方便调试）
deploy/apply_site.sh --site-dir <你的站点目录> --name office --sites-dir ./sites

# 启动巡检（带 RViz 看过程）
GO2_SITES=./sites deploy/run_site.sh office
```

巡检启动后，可以用服务控制开停：

```bash
# 巡检本来就是自动开跑的，这里四条是人工干预：
ros2 service call /patrol/start  std_srvs/srv/Trigger   # 解除暂停/停止后继续
ros2 service call /patrol/pause  std_srvs/srv/Trigger   # 暂停
ros2 service call /patrol/resume std_srvs/srv/Trigger   # 继续
ros2 service call /patrol/stop   std_srvs/srv/Trigger   # 停止本次巡检
```

RViz 里 `/waypoints/markers` 的球会**蓝 → 黄 → 绿**地一个个变，这就是在按顺序巡检。

## 10. 第八步：变成"开机就自动巡检"（交付）

真机交付时不想每次手敲命令，就装成系统服务：

```bash
# 安装 + 编译 + 落地站点 + 装 systemd（一条龙）
sudo deploy/install.sh --iface enp3s0 --site <你的站点目录> --site-name office

# 开机自启并立即启动
sudo systemctl enable --now go2-patrol@office

# 实时看日志
journalctl -u go2-patrol@office -f

# 停止 / 重启
sudo systemctl stop  go2-patrol@office
sudo systemctl restart go2-patrol@office
```

升级和回滚（出问题救命用）：

```bash
sudo deploy/install.sh --repo <仓库地址> --ref v0.2.0     # 装新版本
sudo deploy/install.sh --rollback v0.1.0                  # 切回旧版本
```

启动前自检（不启动也能查问题）：

```bash
deploy/preflight.sh office
```

## 11. 出问题对照表（照着查）

| 现象 | 最可能的原因 | 解决 |
|---|---|---|
| `ros2: command not found` | 没 source 环境 | `cd ~/go2_official_ws && source scripts/setup.sh` |
| `Package 'go2_patrol_bringup' not found` | 没编译 / 没 source | `colcon build` 后 `source install/setup.bash` |
| `ros2 topic list` 卡住不出结果 | DDS 网卡没选对 | `GO2_IFACE=<网卡> source scripts/setup.sh` |
| 话题都没有数据 | 网线/IP/狗状态 | `ping 192.168.123.161` → 查第 5 步 |
| RViz 打不开或看不到窗口 | Windows/WSL 图形通道故障 | `wsl --shutdown` 后重进 WSL 再启动（记录在开发环境文档） |
| 地图糊成一片 | 走太快 / 玻璃镜面反射 | 慢速重走；避开玻璃 |
| 定位粒子乱飞不收敛 | 初始位姿给错 / 地图和现场不一致 | RViz 里重新给 `2D Pose Estimate`；确认加载的是当前地图 |
| Nav2 起不来、容器报错 | 参数文件被改坏 | 用 `git diff` 看 `nav2_params.yaml`；跑 `tools/offline_demo/run_patrol_demo.sh` 复现 |
| 报 TF 冲突 / 定位乱跳 | `base_footprint → base_link` 被重复发布 | 检查是否多处启动 static_transform_publisher |
| 到点误差大（半米以上） | 定位漂移 / 到点容差太松 | 收紧 `arrival_tolerance`；检查 AMCL 收敛；重建地图 |
| 到点后原地转很久 | 点位 `yaw` 与行进方向不匹配 | 站点设 `yaw_mode: travel`（见 9.3） |
| 到点没声音 | 没有对应 wav / 系统没播放器 | 确认 `audio/<speech_id>.wav` 存在；`aplay` 手动试播 |
| 说话一卡一卡的、有明显的停顿感 | 语音落地在"停车之后"播 | 用 `speech_lead_distance: 1.2` 提前播 + `turn_speech` 行进中播 |
| 狗收到指令不动 | 狗没进入可控制状态 / 速度限幅太小 | 看 `/lf/sportmodestate` 是否正常；确认已站起 |
| 狗突然停下（没到点） | 前置急停触发了 | 看日志有没有急停记录；检查前方是否真有障碍 |
| 遥控器接管不了 | 自动导航还在跑 | 先 `ros2 service call /patrol/stop`，或用遥控器抢占 |

## 12. 安全守则（真机必读，别跳）

1. **人永远在 1.5 米内、遥控器在手**，第一次跑某个点位时跟着走。
2. **速度从 0.2~0.4 m/s 起步**，确认急停距离后再往上加（上限 0.7 m/s）。
3. **别一上来就跑整圈巡检**：先单点 → 再两点 → 再整圈。
4. **场地清空**：地面别有杂物、玻璃/镜面别在路线旁、别让人从狗前方穿过。
5. **电量**：低于 20% 本项目会自己返航；但现场第一次跑请保证 80% 以上。
6. **地面**：湿滑/地毯会打滑，打滑会让定位漂移 → 先低速试一段看 `/odom` 和实际是否对得上。
7. **急停优先级**：遥控器 > 服务 `/patrol/stop` > 拔网线（拔网线狗会因收不到指令停下，但不要依赖它）。
