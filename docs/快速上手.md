# Go2 定点自主巡检 · 快速上手

本文是 [`完整部署与使用手册.md`](完整部署与使用手册.md) 的精简版，面向"第一次上手、想尽快跑通"的场景。
深入参数、排错和验收清单以完整手册为准。

术语约定：**<仓库根>** 指本仓库目录（例如 `/home/you/go2-official-patrol`），
本文所有命令里的相对路径都相对它。工作空间目录**不要求**叫 `go2_official_ws`。

---

## 0. 这套东西做什么

让 Go2 按你写好的航点列表自主走一圈，到点播放语音。

- 技术栈：ROS 2 Humble + Nav2 + SLAM Toolbox，使用官方 `unitree_ros2` 消息；
- 雷达：用**机身自带的 4D 雷达（L1/L2）**，不需要外置雷达、不需要拓展坞；
- 反光条虚拟墙是**独立测试项**，默认不接入避障。

链路概览：

```text
机载雷达 /utlidar/cloud_deskewed
      │
      ▼  pointcloud_to_laserscan
    /scan ──┬─→ slam_toolbox（建图）→ /map
            └─→ AMCL + Nav2（定位/导航）
                       │  /cmd_vel
                       ▼
                 twist_bridge（前向减速/急停）
                       │  /api/sport/request
                       ▼
                    Go2 行走
                       │
                       ▼
              patrol_manager → /robot/say → voice_player 播音
```

## 1. 第一次安装

```bash
cd <仓库根>
./scripts/bootstrap.sh
```

`bootstrap.sh` 会：装 Nav2 / SLAM Toolbox / `pointcloud_to_laserscan` / CycloneDDS，
拉取官方 `unitree_ros2`，编译它，再编译本工作空间。

### 设置网卡

必须指定**接狗的那块网卡**，否则收不到话题：

```bash
ip -brief addr                 # 看网卡名，例如 enp3s0 / WLAN
export GO2_IFACE=enp3s0        # 改成你的
source scripts/setup.sh
```

`scripts/setup.sh` 会自动推导工作空间根目录，打印一行
`[setup.sh] GO2 DDS interface: xxx` 表示已生效。

### 验证连接

```bash
ping 192.168.123.161                  # 狗的地址
ros2 topic hz /lf/sportmodestate      # 应有稳定频率
ros2 topic hz /utlidar/cloud_deskewed # 应有稳定频率
```

两条都有频率 = DDS 链路通了。收不到先查网卡名和网线，别急着改代码。

## 2. 三步走

### 第 1 步 · 建图

```bash
source scripts/setup.sh
ros2 launch go2_patrol_bringup mapping.launch.py
```

用遥控器**慢速**走完环境，回到起点附近形成闭环，然后另开一个终端：

```bash
./scripts/save_map.sh office_floor
```

地图存到 `src/go2_patrol_bringup/maps/`。建议命名成 `map.yaml` / `map.pgm`，
这样后面启动不用额外传参数。

在建好的地图里检查：墙线连续、无多层重影、起点附近闭环正常。

### 第 2 步 · 单点导航测试（必做）

```bash
ros2 launch go2_patrol_bringup navigation.launch.py
```

在 RViz 中：

1. 用 `2D Pose Estimate` 给出当前位姿，等 AMCL 粒子收敛；
2. 用 `2D Goal Pose` 点一个目标，看它能否自己走过去。

**这一步必须先跑通再上巡检**，否则问题定位很难。

### 第 3 步 · 航点巡检

编辑 `src/go2_patrol_bringup/config/waypoints.yaml`：

```yaml
waypoints:
  - name: entrance
    x: 0.0
    y: 0.0
    yaw: 0.0
    dwell: 4.0
    speech: entrance        # 对应 audio/entrance.wav
    home: true
  - name: equipment_zone
    x: 2.0
    y: 0.0
    yaw: 0.0
    dwell: 4.0
    speech: equipment_zone
```

| 字段 | 含义 |
|---|---|
| `name` | 巡检点 ID（也用于防止重复播报） |
| `x` / `y` | 地图坐标（米） |
| `yaw` | 到点朝向（弧度） |
| `dwell` | 到点后停留秒数 |
| `speech` | 语音文件 ID，对应 `audio/<speech>.wav` |
| `home` | 预留字段，当前低电量返航固定用第 1 个点 |

**航点坐标怎么采**：导航跑起来且 AMCL 收敛后

```bash
ros2 run go2_patrol_patrol record_waypoint entrance
```

会打印可直接粘进 yaml 的坐标片段。注意它读的是 `/odom`，
所以务必等定位收敛后再采，否则会偏。

**语音**：把 `<speech>.wav` 放进 `src/go2_patrol_patrol/audio/`。
没有对应文件时只在终端打印 `[VOICE] xxx`，不会报错。
可用 `ros2 topic pub --once /robot/say std_msgs/msg/String "{data: entrance}"` 单独测。

启动巡检：

```bash
ros2 launch go2_patrol_bringup patrol.launch.py
```

服务控制：

```bash
ros2 service call /patrol/start  std_srvs/srv/Trigger
ros2 service call /patrol/pause  std_srvs/srv/Trigger
ros2 service call /patrol/resume std_srvs/srv/Trigger
ros2 service call /patrol/stop   std_srvs/srv/Trigger
```

状态语义（本仓库当前实现）：

| 服务 | 行为 |
|---|---|
| `start` | `IDLE` → 开始新一轮并复位进度；`PAUSED` → 等价于 `resume`；`RUNNING` → 拒绝（`success=false`） |
| `pause` | 仅 `RUNNING` 可暂停，同时取消当前 Nav2 目标 |
| `resume` | 仅 `PAUSED` 可恢复，保留航点进度 |
| `stop` | 取消当前目标 + 清空进度 + 回到 `IDLE`；**不会退出进程**，之后可以再次 `start` |

启动后**不会自动开跑**，必须显式调用 `/patrol/start`。

## 3. 没有真机时能测什么

### 3.1 离线演示（假数据 + 建图栈 + RViz）

位置：`tools/offline_demo/`

```bash
tools/offline_demo/run_demo.sh start   # 启动
tools/offline_demo/run_demo.sh stop    # 停止
```

它会启动：

1. `fake_go2.py` —— 模拟 `/lf/sportmodestate`（50Hz 原地旋转）、
   `/lf/lowstate`（1Hz，电量 87%）、`/utlidar/cloud_deskewed`（10Hz，6×8m 房间三维点云）；
2. 一条 `base_footprint → base_link` 静态 TF（补全 TF 链）；
3. `mapping.launch.py`（感知 + 驱动桥 + `slam_toolbox`）；
4. RViz（使用 `tools/offline_demo/demo.rviz`）。

启动后 RViz 里应看到：房间地图（青绿色）、墙壁/箱子扫描点、中心旋转的 odom 箭头。

日志在 `/tmp/demo_*.log`，出问题先看这四个：
`demo_fake.log` / `demo_tf.log` / `demo_mapping.log` / `demo_rviz.log`。

**覆盖范围**：能验证 雷达→`/scan`→SLAM→`/map` 这条建图链路，
以及 TF、`/odom`、`/battery_state`、语音 topic。
**不覆盖**：Nav2 导航与航点巡检（假数据没有真实的可行驶地图和控制器输入）。

### 3.2 纯逻辑单元测试（不需要 ROS）

```bash
/usr/bin/python3 -m pytest src -q
```

当前应为 `16 passed`，覆盖：运动请求构造、航点 YAML 解析、
反光条几何算法、巡检状态机（start/pause/resume/stop 的 12 个用例）。

> 注意：用系统 `/usr/bin/python3`，不要用 conda 的 python（缺 ROS 依赖）。

### 3.3 离线演示时可以用命令自查

```bash
ros2 topic hz /odom
ros2 topic hz /scan
ros2 topic hz /utlidar/cloud_deskewed
ros2 topic echo --once /battery_state
ros2 topic pub --once /robot/say std_msgs/msg/String "{data: entrance}"
ros2 run tf2_ros tf2_echo odom base_footprint
```

对照预期：`/odom` 50Hz、`/scan` 10Hz、`/battery_state` 约 0.87、
`/robot/say` 触发 voice_player 打印 `[VOICE] entrance`。

## 4. 上真机前的安全检查

1. 首次联调把 `twist_bridge` 的 `max_linear` 从 0.7 降到 0.3~0.4；
2. 人站在机器人前方 1.5m 外，发一个近目标，确认它能停；
3. 前方 0.4m 放硬物 → 应减速；前方 0.2m 放硬物 → 应急停；
4. 确认 `/patrol/stop` 能立即取消导航任务；
5. 若机器狗不会自动站起来，先手动发一次：

```bash
ros2 run go2_patrol_driver sport_command balance_stand
```

急停（会让狗软掉，谨慎使用）：

```bash
ros2 run go2_patrol_driver sport_command damp
```

## 5. 常见问题速查

| 现象 | 先查什么 |
|---|---|
| 收不到狗的话题 | `GO2_IFACE` 是不是接狗那块网卡；网线；WSL2 是否开了 mirror 网络 |
| `/scan` 没数据 | `/utlidar/cloud_deskewed` 有没有频率；`base_footprint` TF 是否存在 |
| Nav2 起不来 | 是否已启动 `odom_bridge`；地图路径是否存在；frame 名是否匹配 |
| 狗不动 | 是否 `balance_stand`；`/cmd_vel` 有没有数据；是否被前向安全停下 |
| 语音不响 | `audio/<id>.wav` 是否存在；终端 `aplay <file>` 能否播放 |
| RViz 卡死 | 关掉 PointCloud2 显示；用小窗口；参考手册"问题 16" |

更多细节见 [`完整部署与使用手册.md`](完整部署与使用手册.md)，
雷达与官方 SLAM 服务选型见 [`EDU与L2-官方SLAM导航服务对比.md`](EDU与L2-官方SLAM导航服务对比.md)。
