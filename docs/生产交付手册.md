# Go2 巡检系统 —— 生产交付手册

面向「把工作空间交到另一台生产机器狗上并长期无人值守运行」的场景。
开发环境搭建与日常调试见 [`完整部署与使用手册.md`](完整部署与使用手册.md)，
交付工具包见 [`deploy/README.md`](../deploy/README.md)。

## 1. 交付物清单

| 交付物 | 内容 | 谁产出 |
|---|---|---|
| 代码交付包 | 某个 tag/sha 的完整工作空间（在线 clone 或离线 bundle） | 开发机 `deploy/make_release_bundle.sh` |
| 站点资产 | `map.yaml`/`map.pgm`、`waypoints.yaml`、`site.yaml`、`audio/*.wav` | 现场标定后整理，模板见 `deploy/site.example/` |
| 交付记录 | 版本号、commit、交付日期、验收结论 | 填写本手册第 9 节 |

一个 tag 对应一次可回滚的交付版本；站点资产可以独立于代码更新（换地图、加点位不用重装代码）。

## 2. 生产机前置条件

| 项目 | 要求 |
|---|---|
| 系统 | Ubuntu 22.04（与机器狗官方 SDK 对齐） |
| ROS | ROS 2 Humble Desktop |
| 硬件 | 与机器狗直连的网卡（默认同网段 `192.168.123.x`），机器狗地址默认 `192.168.123.161` |
| 权限 | 交付用账号需 sudo；巡检服务以该账号运行（不需要 root 常驻） |
| 网络 | 在线交付需能访问 GitHub，否则走离线包 |

```bash
# 机器狗直连网卡的常规配置（示例网卡 enp3s0，独立网段不与外网混用）
sudo ip addr add 192.168.123.18/24 dev enp3s0
ping -c 2 192.168.123.161
```

> 网卡名写在 `/etc/go2/site.env` 的 `GO2_IFACE`，或站点 `site.yaml` 的 `iface`。
> 写错时 `preflight.sh` 会以 `[FAIL] 网卡不存在` 拒绝启动，这是刻意设计。

## 3. 安装

### 3.1 在线安装（生产机能访问 GitHub）

```bash
git clone https://github.com/xqd922/go2-official-patrol.git /tmp/go2-src
cd /tmp/go2-src
sudo deploy/install.sh --ref v0.1.0 --iface enp3s0
```

流程：装依赖（清单 `deploy/apt-deps.txt`）→ 克隆到 `/opt/go2/releases/v0.1.0` → `vcs import` 官方 `unitree_ros2` → 编译 → 切 `/opt/go2/current` → 写 `/etc/go2/site.env` → 装 systemd 单元。首次编译约 10–20 分钟。

### 3.2 离线安装（生产机无网）

开发机（在已 `vcs import` 过的副本里执行）：

```bash
deploy/make_release_bundle.sh v0.1.0          # 产物在 dist/
sha256sum dist/go2-official-ws-v0.1.0-bundle.tar.gz
```

生产机：

```bash
# 前提：ROS 2 Humble 与 deploy/apt-deps.txt 里的包已装好（可用同版本 U 盘源）
sudo deploy/install.sh --bundle /media/usb/go2-official-ws-v0.1.0-bundle.tar.gz \
  --ref v0.1.0 --no-apt
```

离线包内含 `offline/unitree_ros2.tar.gz`，因此不需要联网 `vcs import`；安装后版本目录里的 `DELIVERY_MANIFEST.txt` 记录了 commit 与文件校验和。

### 3.3 台架自检（没有真机也先跑一遍）

```bash
# site.example 自带 10m 空地占位地图，可直接当一个演示站点用
sudo deploy/apply_site.sh --site-dir deploy/site.example --name demo
sudo systemctl enable --now go2-patrol@demo
journalctl -u go2-patrol@demo -f
```

需要别的房间尺寸时：`python3 deploy/tools/make_blank_map.py <目录> --size 15 --name demo`。

看到 Nav2 的 lifecycle 节点依次 `configuring → activating → active`，说明「systemd → 环境 → launch → 参数 → Nav2」这条链路已打通。机器狗不在线时驱动桥接会报连接错误，属预期。

## 4. 现场标定（每个站点一次）

在能连上机器狗的机器上做，产物全部放进站点资产目录。

1. **建图**

   ```bash
   source scripts/setup.sh
   ros2 launch go2_patrol_bringup mapping.launch.py
   # 遥控器慢速走完整闭环（转弯处放慢，避免地图错层）
   ./scripts/save_map.sh office_3f
   ```

   产物为 `src/go2_patrol_bringup/maps/office_3f.pgm` + `.yaml`；交付时把它们按 `map.pgm` / `map.yaml` 放进站点目录。

2. **确定固定起点**

   机器狗每次开机都停在同一个位置（充电桩/停机位）。在 RViz 用 `2D Pose Estimate` 对齐后读 `map → base_link` 的位姿，填进 `site.yaml`：

   ```yaml
   initial_pose:
     x: 0.35
     y: -1.20
     yaw: 1.57
   ```

   这个值是**自启巡检能否无人干预**的关键：写错会让 AMCL 定位发散、Nav2 不动作。`apply_site.sh` 会把它写进站点 `nav2_params.yaml` 的 `amcl.set_initial_pose: true`。

3. **标定点位**

   遥控机器狗到每个巡检点，逐点采集：

   ```bash
   ros2 run go2_patrol_patrol record_waypoint equipment_zone
   ```

   把输出粘进站点 `waypoints.yaml`，补 `dwell`（停留秒数）、`speech`（语音 ID），并给起点标 `home: true`。

4. **准备到点语音**

   按点位 `speech` 命名 wav 放进 `audio/`，格式建议见 `deploy/site.example/audio/README.md`。

5. **落地并自检**

   ```bash
   sudo /opt/go2/current/deploy/apply_site.sh --site-dir <站点目录> --name office
   sudo /opt/go2/current/deploy/preflight.sh office
   ```

## 5. 启用服务

```bash
sudo systemctl enable --now go2-patrol@office
systemctl status go2-patrol@office
journalctl -u go2-patrol@office -f
```

服务行为（模板 `deploy/systemd/go2-patrol@.service`）：

- 开机自启（`enable` 后）；异常退出 10 秒后自动拉起，5 分钟内超过 5 次则停止重试，避免空转刷日志；
- 启动前执行 `preflight.sh`：站点资产、网卡等硬性检查不过就不启动；
- `stop` 时发 SIGINT，让 `ros2 launch` 干净退出（Nav2 先停车再退）；
- 日志进 journal，ROS 日志在 `/var/log/go2/ros`；实例名就是站点名，一台机器可挂多个站点（通常只同时跑一个）。

## 6. 日常运维

```bash
# 状态与日志
systemctl status go2-patrol@office
journalctl -u go2-patrol@office -n 200 --no-pager
journalctl -u go2-patrol@office -f

# 启停与开机自启
sudo systemctl start|stop|restart go2-patrol@office
sudo systemctl disable go2-patrol@office     # 取消开机自启

# 手动干预巡检（需先 source 环境）
source /opt/go2/current/deploy/go2_env.sh
ros2 service call /patrol/start std_srvs/srv/Trigger
ros2 service call /patrol/pause std_srvs/srv/Trigger
ros2 service call /patrol/resume std_srvs/srv/Trigger
ros2 service call /patrol/stop std_srvs/srv/Trigger

# 到点语音是否真的下发
ros2 topic echo /robot/say
```

确认链路活着（真机在场时）：

```bash
source /opt/go2/current/deploy/go2_env.sh
ros2 topic hz /lf/sportmodestate       # 运动状态
ros2 topic hz /utlidar/cloud_deskewed  # 机载雷达点云
ros2 topic hz /scan                    # 转出来的 2D 扫描
ros2 topic echo /battery_state --once  # 电量（低电量保护用）
```

## 7. 升级与回滚

```bash
# 升级到新版本（新目录独立编译，成功后切 current 并重启在跑的站点服务）
sudo /opt/go2/current/deploy/install.sh --ref v0.2.0

# 回滚（秒级；站点资产与站点目录都不动）
ls /opt/go2/releases
sudo /opt/go2/current/deploy/install.sh --rollback v0.1.0
```

- 一个版本一个目录，编译互不影响；`current` 是软链，回滚只切链 + 重启服务。
- 站点资产（地图/点位/语音/`site.yaml`）不在版本目录里，升级不会覆盖。
- `nav2_params.yaml` 是生成文件：新版仓库默认参数有调整时，升级后重跑一次 `apply_site.sh` 重新生成。

## 8. 验收清单（交付必须逐条打勾）

**A. 安装与自启**

- [ ] `sudo deploy/install.sh --ref <版本>` 无错误结束，`ls -l /opt/go2/current` 指向正确版本
- [ ] `sudo /opt/go2/current/deploy/preflight.sh <站点>` 输出无 `[FAIL]`
- [ ] `systemctl is-enabled go2-patrol@<站点>` 为 `enabled`
- [ ] 断电重启生产机后无需人工登录即自动运行：`systemctl is-active go2-patrol@<站点>` 为 `active`

**B. 定位与导航**

- [ ] 开机后 `ros2 topic echo /amcl_pose --once` 的位姿与固定起点一致（偏差 < 0.3 m）
- [ ] 临时 `GO2_RVIZ=true` 看 RViz，`map` 与 `/scan` 重合、无明显错层
- [ ] 单目标测试：给一个近点 goal，机器狗到点并停下（在 `arrival_tolerance` 内）

**C. 巡检业务**

- [ ] `/patrol/start` 后按 `waypoints.yaml` 顺序巡航，全部到点、停留时间正确
- [ ] 每个点位的 `speech` 都有对应 wav 且现场实际出声
- [ ] 低电量保护：把阈值临时调到当前电量以上，验证返航行为
- [ ] 前置急停：前方 0.35 m 放障碍物，日志出现 `front safety stop` 且机器狗停住（QoS 修复后这套保护才真正生效，必须现场复核阈值）

**D. 异常恢复**

- [ ] `sudo kill -9` 主进程后 10 秒内自动重启并重新 active
- [ ] 拔掉机器狗网线再插回，任务能恢复（或服务重启后恢复）
- [ ] 把站点 `map.yaml` 改名后重启服务，因 `preflight.sh` 失败而拒绝启动并留下明确日志

**E. 交付记录**

- [ ] 第 9 节填写完整

## 10. 故障排查

| 现象 | 排查顺序 |
|---|---|
| 服务起不来，日志是 preflight `[FAIL]` | 按日志逐项修：站点目录、`map.yaml`/地图数据、`waypoints.yaml`、`nav2_params.yaml`、网卡名 |
| 服务 active 但 Nav2 不 active | `journalctl` 看 lifecycle 报错；常见原因是参数 YAML 结构错、初始位姿越界、`/scan` 无数据 |
| 机器狗不动 | `ros2 topic hz /lf/sportmodestate`、`/scan`、`/cmd_vel` 逐个确认 |
| 到点没声音 | 日志搜 `audio not found`；确认 `audio/<speech>.wav` 存在、`aplay -l` 有设备、`aplay <file>` 能直接播 |
| 定位漂移 / 乱走 | 固定起点是否被挪动、地图是否过期、`robot_radius` 是否过小 |
| 服务反复重启 | `systemctl status` 看是否触发 `StartLimitBurst`；多半是参数/资产硬错误，先手动复现 |
| 升级后行为异常 | `install.sh --rollback <旧版本>`；确认站点资产是否被手工改过 |

手动复现（绕过 systemd，最容易看清报错）：

```bash
GO2_ENV_QUIET=0 sudo -u <用户> -H bash -lc \
  'source /opt/go2/current/deploy/go2_env.sh && /opt/go2/current/deploy/run_site.sh office'
```

## 11. 已知限制与注意事项

- **初始位姿必须先标定**：仓库默认 `nav2_params.yaml` 是 `set_initial_pose: false`，直接用要人工给 `/initialpose`。生产站点必须走 `apply_site.sh` 生成带固定起点的站点副本。
- **生产机不开 RViz**：`run_site.sh` 默认 `rviz:=false`（无显示器会崩）；现场调试可临时 `GO2_RVIZ=true`。
- **单站点单实例**：一台生产机通常只 `enable` 一个站点实例，多实例会争抢 `/cmd_vel` 与导航栈。
- **多机同网段**：多台生产机在同一 ROS 域会互相看见话题，必要时用 `site.yaml` 的 `env: ROS_DOMAIN_ID` 隔离。
- **反光条虚拟墙**未接入 Nav2，见 `完整部署与使用手册.md` 第 16 章。
- **急停以硬件为准**：软件层只做导航避障与任务保护，现场必须保留遥控器/急停通道。
- **首次现场调试建议先降速**：`nav2_params.yaml` 里的速度上限按现场地面/负载验证后再放开。
- **前置急停阈值需现场复核**：`twist_bridge` 的 `/scan` 订阅 QoS 已修（原先 reliable 订阅收不到 best_effort 的扫描，保护静默失效）。修复后 `stop_distance=0.35`、`emergency_distance=0.20` 会真实触发，首跑务必确认不会因点云噪声误停。
