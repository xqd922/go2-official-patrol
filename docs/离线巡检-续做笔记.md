## 一、明天第一件事：先设 Go2 网卡（否则一切都不稳）

**这是今天最大的坑，也是最容易再次踩到的。**

`scripts/setup.sh` 用 `ip route show default` 自动选网卡。在某些环境里
（含本机沙箱）netlink 被禁，`ip route` 直接失败，于是回退到兜底值
`enp3s0` —— 但本机真实网卡是 **`enp49s0`**。网卡不对 → CycloneDDS 发现
极慢 → Nav2 lifecycle 的 `change_state` 服务调用随机超时 →
`Failed to change state` / `Aborting bringup`（表现为 map_server /
controller_server / bt_navigator 间歇性 inactive）。

**跑之前先确认网卡名：**

```bash
ls /sys/class/net/          # 找到真实有线网卡，本机是 enp49s0
```

**启动时显式指定：**

```bash
export GO2_IFACE=enp49s0    # 换成你机器上的实际网卡名
```

注意：`ip route` 在某些受限 shell 里也会失败，所以别只看 setup.sh 打印的
`[setup.sh] GO2 DDS interface: xxx` 就以为对了 —— 它可能是兜底值。
如果这个环境限制消失（普通终端下 `ip route` 正常），自动检测是对的，
就不需要手动设 `GO2_IFACE`。

## 二、复现命令

```bash
cd /home/lzc/go2-official-patrol
export GO2_IFACE=enp49s0
source /opt/ros/humble/setup.bash
source install/setup.bash
export PATH=/usr/bin:$PATH ROS_LOG_DIR=/tmp/roslog   # 注意用 /usr/bin/python3
mkdir -p /tmp/roslog                                  # $HOME/.ros/log 可能不可写

# 起离线巡检（含 RViz）
tools/offline_demo/run_demo.sh patrol
# 或直接：
ros2 launch go2_patrol_bringup offline_patrol.launch.py

# 触发巡检
ros2 service call /patrol/start std_srvs/srv/Trigger
# 停止
tools/offline_demo/run_demo.sh stop
```

**环境要点（每天都会踩）：**
- `python3` 默认是 conda 3.14，**没有 rclpy**，节点会启动即崩。
  一律用 `/usr/bin/python3`（3.10）。
- `colcon build` 也要 `PATH=/usr/bin:$PATH`。
- `$HOME/.ros/log` 可能不可写 → 设 `ROS_LOG_DIR=/tmp/roslog`。
- 清理进程**不要**用会匹配到自身命令行的 `pkill` 模式（会把自己 shell 杀掉，
  exit 143）。用 `[x]` 技巧或按 PID kill。

## 三、剩余问题（按优先级）

### 问题 1：Nav2 bringup 仍然间歇性失败（**主要阻塞**）

症状：`lifecycle_manager` 报 `Failed to change state for node: map_server`
或 `controller_server`，随后 `Aborting bringup`。日志里能看到节点的
`Configuring` **晚于** manager 放弃的时刻 —— 说明 change_state 发得太早，
节点还没准备好处理请求。

**今天的半成品**：`tools/offline_demo/nav2_starter.py`
- 思路：Nav2 用 `autostart:=false` 启动，该节点先等每个 lifecycle 节点的
  `get_state` 服务真正可用，再发 `manage_nodes STARTUP`，最后轮询到
  **每个节点确实 active** 才退出。
- 已接入 `offline_patrol.launch.py`，`navigation.launch.py` 的离线分支
  已传 `autostart:=false`、`use_composition:=False`、`bond_timeout:=20.0`。
- **还没验证成功**（最后一次完整运行被打断了）。
- 明天要做的：跑一次，确认 starter 打出「Nav2 全部 lifecycle 节点已 active」，
  且 8 个节点 `ros2 lifecycle get` 全 active。

注意 starter 的输出在它自己的 roslog 里，不在 launch 的 stdout：
`find /tmp/roslog -name "*nav2_starter*"` 或在 launch 输出里找
`[nav2_starter-N]: process has finished cleanly`（exit 0 = 成功）。

如果这条路仍不稳，备选：
- 给 lifecycle_manager 传更大的 `bond_timeout`（已加 20.0）；
- 或把 Nav2 拆成「先起节点 → 单独一条命令触发 bringup」，人工分步定位。
