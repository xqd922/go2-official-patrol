# Go2 巡检系统 实施方案

> 适用范围：宇树 Go2 + 机载 4D 激光雷达（L1/L2）方案，不依赖官方 `slam_operate` 与外置雷达。
> 本文与仓库当前实现一一对应，接口名、参数值均取自代码。

> **一句话方案**：以宇树 Go2 为硬件平台，用 **SLAM Toolbox 完成实时 2D 地图与定位**，
> 交给 **Nav2 做路径规划、避障与运动控制**，上层按航点顺序巡检、到点与转弯时播报语音——
> 感知 / 决策 / 控制分层解耦，换站点只改配置不改代码。

## 1. 总体框架

以宇树 Go2 为硬件平台、ROS 2 为软件框架：机载 4D 激光雷达实时采集环境点云，
SLAM Toolbox 同步构建 2D 地图并提供定位，Nav2 基于该地图完成全局与局部路径规划、
避障和运动控制；上层巡检调度模块按航点顺序下发导航目标，到点触发语音播报；
整套链路配有离线仿真验收和生产机一键部署能力。

### 系统流程

```text
雷达点云 → SLAM Toolbox（实时 2D 地图 + 定位）→ Nav2（路径规划 / 避障 / 控制）→ 巡检调度（航点 + 语音）→ Go2 运动
```

## 2. 建设目标

在 Go2 上实现"建图 → 定位 → 导航 → 航点巡检 → 到点语音"全自主闭环，并能复制到多台机器狗批量交付。

| 能力 | 目标 |
|---|---|
| 建图 | 用机载雷达完成站点 2D 栅格地图，无需外置设备 |
| 导航 | 单点目标可靠到达，到点误差 ≤ 0.30m（Nav2 goal_checker） |
| 巡检 | 多航点顺序巡检；圈数、收工返航、低电量返航策略可配置 |
| 语音 | 到点播放预录音频，不依赖相机与在线 TTS |
| 验收 | 离线端到端自动断言（顺序 / 精度 / 行程 / 播报），可作交付依据 |
| 交付 | 生产机一键安装、开机自启、崩溃重启、秒级升级回滚 |

## 3. 技术选型

| 层次 | 选型 | 说明 |
|---|---|---|
| 机器人平台 | 宇树 Go2 | 机载 4D 激光雷达 L1（约 11Hz/2000 点/圈）或 L2（约 5.55Hz/11500 点/圈） |
| 运行环境 | Ubuntu 22.04（开发用 WSL2） | 生产机为狗配套工控机 / 笔记本 |
| 中间件 | ROS 2 Humble + CycloneDDS | 官方 `unitree_ros2` 消息，`repos/` 钉版本，避免其它 DDS 抢占话题 |
| 建图 | SLAM Toolbox（sync 模式） | 建图阶段实时输出 2D 地图，`/slam_toolbox/save_map` 保存为 pgm/yaml |
| 定位 | AMCL（300~1000 粒子） | 导航阶段基于静态地图定位，输出 `map → odom` TF |
| 规划控制 | Nav2（Bringup） | 全局规划（默认 NavFn）、Regulated Pure Pursuit 控制器、voxel/static 代价地图、行为树导航 |
| 感知转换 | `pointcloud_to_laserscan` | 点云 → `/scan`（高 0.05~1.20m、360°、0.15~20m） |
| 语音 | 预录 `.wav` + 系统播放器 | 到点播报 + **转弯行进中播报**（`turn_speech`）；优先 `aplay`，WSL 下借 Windows 扬声器，无在线 TTS 依赖 |
| 交付 | `deploy/` 工具包 + systemd | `/opt/go2/releases/<版本>` + `current` 软链 + 站点资产目录 |

## 4. 系统架构（分层）

```text
任务层       patrol_manager / patrol_sequence / voice_player / record_waypoint
规划控制层   Nav2（planner_server / controller_server / costmap / bt_navigator）+ AMCL + map_server
感知驱动层   pointcloud_to_laserscan / odom_bridge / battery_bridge / twist_bridge
机体接口层   /lf/sportmodestate  /lf/lowstate  /utlidar/cloud_deskewed  /api/sport/request
```

| 模块 | 职责 | 关键接口 |
|---|---|---|
| `go2_patrol_driver` | 机体桥接：里程计/IMU/电量上报，速度指令下发，前置急停 | `/lf/sportmodestate` → `/odom`、`/lf/imu`；`/cmd_vel` → `/api/sport/request` |
| `go2_patrol_bringup` | 感知转换、SLAM/Nav2 参数、launch、RViz 巡检视图 | `/utlidar/cloud_deskewed` → `/scan`；`/map`、`/plan` |
| `go2_patrol_patrol` | 巡检调度、状态机、语音播放、航点采集 | 服务 `/patrol/start|pause|resume|stop`；话题 `/robot/say`、`/waypoints/markers` |
| `go2_patrol_reflective` | 反光条虚拟墙测试项（只输出 Marker/状态，不接避障） | `/reflective_wall_status`、`/reflective_wall_markers` |
| `tools/offline_demo` | 假狗 + 假数据，端到端自动验收 | 退出码 + `/tmp/go2_offline_demo/report.json` |
| `deploy/` | 生产交付：安装、站点落地、systemd、升级回滚 | `install.sh` / `apply_site.sh` / `run_site.sh` |

## 5. 数据流与关键接口

**主链路（巡检运行态）**

1. 感知：`/utlidar/cloud_deskewed` → `pointcloud_to_laserscan` → `/scan`（best_effort QoS）
2. 定位：AMCL 消费 `/scan` + 静态地图，发布 `/amcl_pose` 与 `map → odom` TF
3. 规划控制：Nav2 输出 `/cmd_vel` → `twist_bridge`（限速 + 前置急停）→ `/api/sport/request` → 狗运动
4. 状态反馈：`/lf/sportmodestate` → `odom_bridge` → `/odom` + `odom → base_footprint` TF + `/lf/imu`；`/lf/lowstate` → `/battery_state`
5. 任务调度：`patrol_manager` 向 Nav2 下发 `NavigateToPose`；到点发 `/robot/say` → `voice_player` 播 `audio/<speech_id>.wav`；同时刷新 `/waypoints/markers`

**TF 链**

```text
map ──(AMCL)──► odom ──(odom_bridge)──► base_footprint ──► base_link ──(static, z=0.13)──► utlidar_lidar
```

> `base_footprint → base_link` 仅允许一处发布：机器人自身若有该 TF，现场不要再补
> `static_transform_publisher`，重复发布会让 Nav2 报 TF 冲突。

**服务与可视化**

| 接口 | 说明 |
|---|---|
| `/patrol/start` `/pause` `/resume` `/stop` | 巡检启停控制（std_srvs/Trigger） |
| `/slam_toolbox/save_map` | 建图阶段存图（`scripts/save_map.sh` 调用） |
| `/waypoints/markers` | 点位状态球：蓝=未访问、黄=当前目标、绿=已到达、红=返航点 |
| `/plan` `/local_plan` `/amcl_pose` `/particle_cloud` | RViz 巡检视图（`patrol.rviz`）显示项 |

## 6. 关键设计说明

- **巡检调度与验收共用一份状态机**：`patrol_sequence.py` 是纯逻辑类（阶段 `patrol → return_home → done`，
  支持圈数、收工返航、低电量返航），线上节点与离线验收器引用同一份规则，避免"验收脚本自己实现一套"。
- **到点判定双重校验**：Nav2 `goal_checker` 容差 0.30m/0.35rad；`patrol_manager` 再用 `/amcl_pose`
  复核一次实际位置，超出期望容差会告警提示（防"报成功但没走到位"）。
- **安全限速与前置急停**（`twist_bridge`）：速度限幅 0.7 m/s / 1.0 rad/s；前方 0.60m 内减速 50%、
  0.35m 内停车、0.20m 内紧急停车并保持 0.4s 刹停指令；急停基于 `/scan`，使用 sensor QoS 订阅防静默失效。
- **两阶段建图/导航**：先 SLAM Toolbox 建图存盘，再以静态地图 + AMCL 导航——地图稳定、
  定位可复现，适合固定路线巡检；区别于"边建图边导航"（仅探索用）。
- **站点参数化**：站点差异（固定起点初始位姿、巡检参数、网卡、RViz 开关）集中在站点 `site.yaml`，
  由 `render_site.py` 生成站点 `nav2_params.yaml` / `site.env` 并自检，现场不改代码。
- **Nav2 参数四坑已修复固化**（详见 README「真机联调须知」）：缺 `map_server` 段、插件参数写成标量、
  costmap 插件缺配置块、`bt_navigator` 空行为树。
- **现场临时障碍会自动绕**：静态地图只录墙体、桌子是巡检当天才摆进场地时，Nav2 的
  代价地图（voxel + inflation）会在激光看到桌子后把它标进局部代价，全局规划随即改道——
  不需要重做地图。离线闭环实测（桌 0.6×0.6m、`robot_radius` 0.35m、`inflation` 0.45m）：

  | 桌子与墙的缝隙 | 机器人走法 | 实测路径长 |
  |---|---|---|
  | 0.15 m（狗进不去） | 从桌子的另一侧绕行 | 4.54 m |
  | 0.70 m | 仍走另一侧（含膨胀层后过窄） | 4.83~4.94 m |
  | 0.90 m | 仍走另一侧 | 5.01~5.11 m |
  | 1.15 m | 从缝隙中穿过 | 4.47 m |

  结论：缝宽要 ≥ `2×(robot_radius+inflation)` ≈ 1.6m 才会被当成"通道"；
  小于该宽度时规划器宁可靠外侧绕，不会硬挤、也不会卡死（实测整圈 7/7 点、0 次失败）。
- **边走边说、不打断行进**：语音有两个触发点——`speech_lead_distance`（launch 默认关闭，
  演示站点取 1.20m）在**还没停**时
  就预告下一个点位，`turn_speech` 在**转弯（|w| ≥ `turn_speech_w`）瞬间**播"转弯，请注意安全"，
  并有 `turn_speech_min_interval`（默认 6s）冷却防刷屏。播放在独立节点线程里执行，
  不阻塞导航控制，因此听感是行进中插话而不是停车念稿。
- **到点朝向跟随行进方向（`yaw_mode`）**：点位 `yaw` 若与行进方向无关，到点要先转身到位、
  起步再转回来，一个拐角最坏白转 270°，现场感受就是"总是原地转半天"。
  `yaw_mode: travel`（路口）/ `next`（下一段）/ `fixed`（要正对设备拍照的点，可逐点覆盖）
  让朝向跟实际行进方向走；实测整圈 85.0s → 80.5s，原地转 1154° → 690°、占时 27% → 11%。

## 7. 实施步骤

| 阶段 | 主要工作 | 产出 / 验收 |
|---|---|---|
| 1. 环境与连通 | `bootstrap.sh` 装依赖与官方依赖；`setup.sh` 加载环境；连通性自检 | `/lf/sportmodestate` ≈50Hz、点云有频率 |
| 2. 站点建图 | `mapping.launch.py` + 遥控器慢速闭环，`save_map.sh` 存图 | 站点 `.pgm/.yaml` 地图 |
| 3. 导航调通 | `navigation.launch.py`；给初始位姿、单点目标测试；速度/急停标定 | 可规划、可到达、定位收敛 |
| 4. 巡检落地 | 配置 `waypoints.yaml` + 语音资产；`patrol.launch.py` 跑通；服务控制验证 | 按顺序巡检、到点播报、低电量返航 |
| 5. 离线验收 | `run_patrol_demo.sh` 端到端自动断言；纳入 CI | 全部断言通过、退出码 0 |
| 6. 生产交付 | `install.sh` → `apply_site.sh` → `systemctl enable go2-patrol@<站点>` | 开机自启、崩溃重启、回滚演练通过 |

## 8. 验收标准

**离线自动验收**（`tools/offline_demo/`，作为交付门槛）

| 断言 | 阈值 |
|---|---|
| 到点顺序 | 与 `waypoints.yaml` 完全一致 |
| 到点精度 | 每点 AMCL 位姿误差 ≤ 0.40m |
| 累计行程 | ≥ 5m（防"原地抖动也算过"） |
| 语音链路 | 到点确实下发播报 |

**真机确认清单**

- `/lf/sportmodestate`、`/utlidar/cloud_deskewed` 均有频率
- TF `base_footprint → base_link` 仅一处发布
- AMCL 粒子收敛后才下发目标；到点误差符合现场要求
- 语音文件存在且可播（`aplay <文件>` 自测）
- 急停在手，速度上限按现场地面/负载复核（建议 0.3~0.6 m/s 起步）

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|:--|---|---|
| L2 雷达 5.55Hz 低频 | 高速下避障反应距离不足 | 巡检限速 0.3~0.6 m/s 起步验证急停距离 |
| Nav2 参数误改 | 起不来 / 整栈段错误 | 四类坑已修复并在参数文件中注释固化，改动需跑离线验收 |
| TF 重复发布 | Nav2 报 TF 冲突、定位异常 | 上机前检查 `base_footprint → base_link` 发布源唯一 |
| 定位漂移 | 巡检点偏移、乱走 | 固定起点 + 地图定期维护 + 到点 AMCL 复核告警 |
| 现场临时障碍（桌子、箱子、走动的人） | 原路线被占，硬挤或卡死 | 局部代价地图自动绕行；缝隙 < 1.6m 时规划器改走外侧（已离线实测），现场仍需留出足够通行宽度 |
| 站点差异被写进代码 | 换站点即返工 | 差异全部集中 `site.yaml`，`apply_site.sh` 生成并 preflight |
| 现场语音设备差异 | 到点无声 | `aplay` 优先，自动回退 `afplay`/`ffplay`；交付前逐条试播 |

## 10. 与同类开源方案对照（GO2-Patrol-Nav）

对照对象：<https://github.com/liangc001/GO2-Patrol-Nav>（依据其 README 描述，2026-10 查阅）。

| 维度 | 本项目 | GO2-Patrol-Nav |
|---|---|---|
| 系统 / ROS | Ubuntu 22.04 + ROS 2 **Humble**（支持到 2027） | Ubuntu 20.04 + ROS 2 **Foxy**（已 EOL，README 注明"仅支持 20.04"） |
| 与狗通信 | 官方 `unitree_ros2` + CycloneDDS 局域网直连 | Unitree SDK2 + **WebRTC**（LocalSTA 直连 192.168.123.161） |
| 巡检执行 | Nav2 `bt_navigator` + 自研状态机（圈数 / 返航 / 低电量） | 自研 `path_runner.py` 读 `commands.yaml` 逐点执行 |
| 建图定位 | SLAM Toolbox 建图 → 静态地图 + AMCL 定位（两阶段） | SLAM Toolbox 建图 + Nav2 导航包 |
| 额外感知 | 反光条测试项（未接入避障） | **YOLOv5 目标检测**（GPL-3.0，需相机） |
| 远程操控 | 无（不是第一阶段目标） | **WebRTC 图传 + Web 控制台** |
| 语音播报 | 到点 + 转弯提醒（预录 wav，离线可用） | README 未描述 |
| 自动验收 | 离线端到端断言 + `report.json` | README 未描述（仿真 / 真机手跑） |
| 交付方式 | `install.sh` / `apply_site.sh` / systemd / 升级回滚 | 手动改脚本路径与 IP、逐个 `.sh` 启动 |

**结论**

- 作为**巡检导航主线**，本项目更合适：ROS 2 版本在维护期内、导航用 Nav2 标准栈（自带恢复行为）、
  有可复现的自动验收和站点化交付；对方 README 未描述动态重规划与失败恢复，路径执行偏"录制回放"。
- 对方的**可借鉴点**：WebRTC 图传 + Web 控制台（远程看画面、点按钮）、地图上点选航点、
YOLOv5 检测项。这些可作为二期增强，不影响现有导航链路。
- 若要用对方代码，注意 Foxy / Ubuntu 20.04 环境、硬编码路径与 IP、YOLOv5 的 GPL-3.0 许可证。
