# Go2 Official Stack Patrol Workspace 完整手册

本文档对应 `go2_official_ws` 当前实现。基于 **Unitree 官方 `unitree_ros2`** 和 **ROS 2 Humble / Nav2 / SLAM Toolbox**，实现 Go2 的建图、定位、自主导航、按航点巡检、到点语音。**反光条识别已作为测试项加入，未接入避障。**

## 1. 当前实现状态

已完成：

| 模块 | 状态 | 说明 |
|---|---:|---|
| 官方 Unitree 消息桥 | 已实现 | `unitree_go` / `unitree_api` 消息与运动控制请求 |
| 里程计/TF 桥 | 已实现 | `/lf/sportmodestate` → `odom -> base_footprint` |
| 速度控制桥 | 已实现 | `/cmd_vel` → `/api/sport/request` |
| 前向安全减速/停车 | 已实现 | `/scan` 前向扇区距离判断 |
| 机载 4D 雷达点云转 `/scan` | 已实现 | 兼容 L1/L2，使用官方 `pointcloud_to_laserscan` |
| SLAM 建图 | 已实现 | `slam_toolbox` |
| Nav2 定位导航 | 已实现 | Nav2 Bringup + AMCL + RViz |
| 航点巡检状态机 | 已实现 | 基于 `nav2_simple_commander` |
| 到点语音 | 已实现 | 到点后发布 `/robot/say`，播放预录 WAV |
| 反光条虚拟墙测试 | 已实现测试项 | 需点云含 `intensity`；输出 Marker/状态，不接入 Nav2 |

真机联调尚未完成前，不要信任自动化运行为“已验收”。本文档中的每一步都应按现场实测确认。

## 3. 环境要求

推荐环境：

| 项目 | 要求 |
|---|---|
| 系统 | Ubuntu 22.04 |
| ROS 2 | Humble |
| 连接 | 千兆有线网，电脑与 Go2 同网段 |
| 电脑 IP | 常用 `192.168.123.99`（官方另建议 `192.168.123.222`；禁止设为 `192.168.123.161`，那是 Go2 机载电脑地址） |
| 子网掩码 | 常用 `255.255.255.0` |

当前设计以控制电脑为主控，语音默认从控制电脑播放。机器人本体播放音频未作为第一阶段必选项。

## 4. 首次安装

### 4.1 准备 ROS 2 Humble

假设 ROS 2 Humble 已经安装。如未安装，先按 ROS 2 官方文档安装 Desktop 版本。不要使用 ROS 2 Foxy。

### 4.2 拷贝工作空间

如果从 Windows 侧复制，可参考：

```bash
cp -a /mnt/d/Desktop/robot/dog/go2_official_ws ~/go2_official_ws
cd ~/go2_official_ws
chmod +x scripts/*.sh
```

### 4.3 安装并编译

```bash
cd ~/go2_official_ws
./scripts/bootstrap.sh
```

`bootstrap.sh` 会：

1. 安装 Nav2、SLAM Toolbox、`pointcloud_to_laserscan`、CycloneDDS、colcon、vcstool；
2. 从 `repos/go2_official_ws.repos` 拉取 `unitreerobotics/unitree_ros2`；
3. 编译 `unitree_ros2/cyclonedds_ws`；
4. 编译本工作空间。

### 4.4 设置网卡

编辑或临时导出实际网卡名：

```bash
export GO2_IFACE=enp3s0
source ~/go2_official_ws/scripts/setup.sh
```

也可以直接把 `scripts/setup.sh` 中的默认值改为你机器的网卡名。

### 4.5 验证连接

```bash
ping 192.168.123.161
ros2 topic list
```

应能看到官方 Unitree 相关话题。不同固件/模式下具体名字可能带或有差别，请以实际输出为准：

```text
/lf/sportmodestate
/lf/lowstate
/utlidar/cloud_deskewed
/api/sport/request
```

再检查数据频率：

```bash
ros2 topic hz /utlidar/cloud_deskewed
ros2 topic hz /lf/sportmodestate
```

如果点云无数据，优先检查网线、IP、网卡名和 `CYCLONEDDS_URI`。

## 6. 关键话题与参数

### 驱动节点

| 节点 | 输入 | 输出 | 作用 |
|---|---|---|---|
| `odom_bridge` | `/lf/sportmodestate` | `/odom`，`/go2/current_pose`，TF | Go2 位姿转换为导航可用里程计 |
| `battery_bridge` | `/lf/lowstate` | `/battery_state` | 电量转换 |
| `twist_bridge` | `/cmd_vel`，`/scan` | `/api/sport/request` | 安全过滤后执行 Nav2 速度 |
| `sport_command` | 命令行动作 | `/api/sport/request` | 手动站立、停止、休眠等 |

`twist_bridge` 当前参数：

| 参数 | 默认值 |
|---|---:|
| `max_linear` | 0.7 m/s |
| `max_angular` | 1.0 rad/s |
| `stop_distance` | 0.35 m |
| `slow_distance` | 0.60 m |
| `emergency_distance` | 0.20 m |
| `front_half_angle_deg` | 30° |

首次真机建议手动把 `max_linear` 降到 0.3～0.4，确认安全后再逐步放宽。

> **前置急停依赖 `/scan` 的 QoS（已修复）**
>
> `pointcloud_to_laserscan` 以 **best_effort** 发布 `/scan`，而 `twist_bridge` 早期用
> 默认的 **reliable** 订阅，两者不兼容：日志会出现
> `incompatible QoS ... RELIABILITY`，`twist_bridge` **收不到任何扫描数据**，
> 于是 `stop_distance` / `emergency_distance` 这套前置急停从未真正生效。
> 现已改为 `qos_profile_sensor_data` 订阅（见 `twist_bridge.py`）。
> 修复后这套保护会真的动作，**首次上真机必须按第 11 节重新验证 0.35 m 停车 / 0.20 m 急停阈值**，
> 若点云噪声导致误停，按现场实际调整 `stop_distance` / `slow_distance` / `front_half_angle_deg`。

```bash
cd ~/go2_official_ws
source scripts/setup.sh
ros2 launch go2_patrol_bringup mapping.launch.py
```

该命令会启动：

- 机载 4D 雷达点云转 `/scan`
- 官方 Unitree 驱动桥
- `slam_toolbox`

### 7.2 保存地图

用遥控器慢速走完环境后：

```bash
./scripts/save_map.sh office_floor
```

保存后检查 `src/go2_patrol_bringup/maps/` 下是否生成对应 yaml/pgm/map 文件。要用于后续导航，可将文件命名为：

```text
src/go2_patrol_bringup/maps/map.yaml
```

或在启动导航时指定：

```bash
ros2 launch go2_patrol_bringup navigation.launch.py \
  map:=/home/<user>/go2_official_ws/src/go2_patrol_bringup/maps/office_floor.yaml
```

地图质量检查：

- 墙线连续，无明显多层重影；
- 起点附近闭环正常；
- 不应有围绕机器人大范围的糊状点；
- 不应把反光条误大面积烧进地图。

## 8. 导航

```bash
cd ~/go2_official_ws
source scripts/setup.sh
ros2 launch go2_patrol_bringup navigation.launch.py
```

启动后在 RViz：

1. 使用 `2D Pose Estimate` 给初始位姿；
2. AMCL 粒子应收敛到机器人附近；
3. 使用 `2D Goal Pose` 给单点目标；
4. 机器狗应自主规划并到达。

当前导航速度与目标容差主要在：

```text
src/go2_patrol_bringup/config/nav2_params.yaml
```

重点参数：

| 参数 | 当前默认 |
|---|---:|
| `desired_linear_vel` | 0.5 m/s |
| `xy_goal_tolerance` | 0.30 m |
| `yaw_goal_tolerance` | 0.35 rad |
| `robot_radius` | 0.35 m |
| `inflation_radius` | 0.45 m |

现场如果穿过狭窄区域失败，先不要盲目增大速度，应重新标定边界和 danger zone。

## 9. 巡检

### 9.1 修改航点

编辑：

```text
src/go2_patrol_bringup/config/waypoints.yaml
```

示例：

```yaml
waypoints:
  - name: entrance
    x: 0.0
    y: 0.0
    yaw: 0.0
    dwell: 4.0
    speech: entrance
    home: true

  - name: equipment_zone
    x: 2.0
    y: 0.0
    yaw: 0.0
    dwell: 4.0
    speech: equipment_zone
```

字段说明：

| 字段 | 说明 |
|---|---|
| `name` | 巡检点 ID，也用于防重复播报 |
| `x` / `y` | 地图坐标 |
| `yaw` | 到点朝向 |
| `dwell` | 到点后等待秒数 |
| `speech` | 语音文件 ID，对应 `audio/<speech_id>.wav` |
| `home` | 预留字段；当前低电量返航会优先使用第一个点位 |
| `yaw_mode` | 该点的到点朝向策略，覆盖站点 `patrol.yaw_mode`（见下） |

### 9.1.1 到点朝向 `yaw_mode`：别让机器人"到点先转半天"

**现象**：走到角落时机器人原地转很久才继续走。**原因不是定位或规划出错**，而是点位 `yaw`
和行进方向无关：到点必须先转到配置的朝向（最多 180°），起步去下一个点又要转回来（再 90°），
一个角最坏白转 270°。离线演示实测（90s 窗口）：旧配置 13 次原地转、合计 1154°、占时 27%。

| `yaw_mode` | 含义 | 适用 |
|---|---|---|
| `fixed`（默认） | 用 `waypoints.yaml` 里的 `yaw` | 要正对设备拍照/读表的点 |
| `travel` | 到点朝"进点方向"，到点不用转身 | 纯路口、过道拐角 |
| `next` | 到点朝"下一段方向"，起步不用转身 | 想一起步就走直的点 |

站点级默认写在 `site.yaml` 的 `patrol.yaw_mode`，个别点可在 `waypoints.yaml` 里写
`yaw_mode: fixed` 单独覆盖（演示站点就是：路口 `travel`，返航点和设备点 `fixed`）。

实测（同一场景，整圈 7 个点）：

| 配置 | 整圈耗时 | 原地转次数 | 原地转总角度 | 原地转占时 |
|---|---|---|---|---|
| `fixed` + 默认 `min_angle` | 85.0s | 13 | 1154° | 24.2s（27%） |
| `travel` + `min_angle: 0.90` | 86.5s | 12 | 752° | 12.3s（13%） |
| **`travel` + 默认 `min_angle: 0.785`** | **80.5s** | **10** | **690°** | **10.8s（11%）** |

> 注意第二行：把 `rotate_to_heading_min_angle` 调大只是把"停车转"换成"低速蠕行掰方向"
> （实测 `v≈0.12 m/s`、`w≈0.84 rad/s`），原地转时间是少了，但整圈更慢。想更快应该
> 提高角速度上限（`twist_bridge` 的 `max_angular`，默认 1.0 rad/s，会截掉控制器更高的转速命令），
> 而不是放松这个角度阈值。

### 9.2 采集航点

导航启动后：

```bash
ros2 run go2_patrol_patrol record_waypoint test_point
```

该工具读取 `/odom`，输出一段可直接贴进 `waypoints.yaml` 的 YAML 草稿。

注意：先用 AMCL 收敛后的地图坐标再作为巡检点，避免 odom 漂移。

### 9.3 启动巡检

```bash
ros2 launch go2_patrol_bringup patrol.launch.py
```

可指定地图和航点：

```bash
ros2 launch go2_patrol_bringup patrol.launch.py \
  map:=/path/to/map.yaml \
  waypoints_file:=/path/to/waypoints.yaml
```

启动后调用：

```bash
ros2 service call /patrol/start std_srvs/srv/Trigger
```

暂停：

```bash
ros2 service call /patrol/pause std_srvs/srv/Trigger
```

继续：

```bash
ros2 service call /patrol/resume std_srvs/srv/Trigger
```

停止：

```bash
ros2 service call /patrol/stop std_srvs/srv/Trigger
```

当前巡检状态机会在每个点到达后：

1. 发送 `/robot/say`；
2. 等待该点 `dwell`；
3. 进入下一个点；
4. 跑完 `loops` 次后停止。

电量低于 `battery_low` 时会取消当前任务并转向第一个航点。

## 10. 语音

把预录音频放进：

```text
src/go2_patrol_patrol/audio/
```

如：

```text
entrance.wav
equipment_zone.wav
return_home.wav
```

`voice_player` 播放逻辑：

1. 收到 `/robot/say`；
2. 根据 `speech_id` 找 `audio/<speech_id>.wav`；
3. 如果有音频，优先调用系统播放器；
4. 如果没有音频，仅在终端打印 `[VOICE] ...`；
5. 播放后有短冷却，避免重复触发。

### 生成中文播报（Windows 自带语音合成，离线）

没有现成录音时，用 Windows 的 SAPI 中文语音生成话术（改 `deploy/site.example/voice_lines.json`
里的 `speech_id → 话术`，然后）：

```powershell
powershell -ExecutionPolicy Bypass -File deploy/tools/make_voice_wavs.ps1 -OutDir deploy/site.example/audio

# 只生成某个 id（例如转弯提醒），用于离线演示站点
powershell -ExecutionPolicy Bypass -File deploy/tools/make_voice_wavs.ps1 `
    -OutDir tools/offline_demo/site-demo/audio -Ids turn_careful
```

产物是 16-bit 单声道 PCM WAV（22050Hz），Ubuntu 的 `aplay`、Windows 的 `Media.SoundPlayer`
都能直接播。离线演示的提示音生成器 `tools/offline_demo/make_demo_audio.py` 默认**不覆盖**
已存在的 wav，所以先放真人语音就会一直用真人语音；要回到提示音加 `--force`。

### 边走边说：到点预告与转弯提醒

| 参数 | 默认 | 作用 |
|---|---|---|
| `speech_lead_distance` | 0.0（演示站点 1.2） | 距目标还有这么多米就先播报，避免"停下来才念" |
| `turn_speech` | 空（关闭） | 转弯时播报的语音 ID，如 `turn_careful` |
| `turn_speech_w` | 0.30 | 角速度阈值（rad/s），超过才算转弯 |
| `turn_speech_min_interval` | 6.0 | 两次转弯提醒的最小间隔（秒） |

语音在独立线程播放，不阻塞导航；`patrol_manager` 的日志会记录播报时刻的速度
（`播报 turn_careful（转弯提醒 v=0.50m/s w=-0.33rad/s）`），可用于确认是"行进中说"还是"停下说"。

手动测试语音：

```bash
ros2 topic pub --once /robot/say std_msgs/msg/String "{data: entrance}"
```

播放命令优先级：

| 平台 | 播放器 |
|---|---|
| Ubuntu | `aplay` |
| macOS | `afplay` |
| 回退 | `ffplay` |

若要机器人本体播放，先确认机载系统是否能访问音频设备，再部署节点到机身端。

## 11. 运动安全测试

任何自动导航前，先控制急停方式。

1. 把 `max_linear` 设置为 0.2～0.4；
2. 让人站在机器人前方 1.5m 外；
3. 测试缓慢目标，确认能停；
4. 前方 0.4m 放硬物，确认 `twist_bridge` 减速/停车；
5. 前方 0.2m 放硬物，确认急停；
6. 确保 `ros2 service call /patrol/stop std_srvs/srv/Trigger` 有效；
7. 需要时再测试 `damp` 或遥控器急停。

手动稳定/停止：

```bash
ros2 run go2_patrol_driver sport_command balance_stand
ros2 run go2_patrol_driver sport_command stop_move
```

## 13. 常见问题

### 点云没有频率

排查顺序：

1. `ping 192.168.123.161` 是否通；
2. 网线是否接在正确口；
3. `GO2_IFACE` 是否真实网卡；
4. `CYCLONEDDS_URI` 是否找到该网卡；
5. 是否有其他 DDS 环境干扰；
6. 机器人是否已经发布雷达数据；
7. `ros2 dl list` / 别的官方例程是否能收到。

### `/scan` 无输出

1. `/utlidar/cloud_deskewed` 是否有数据；
2. `base_footprint` 是否存在；
3. `utlidar_lidar` TF 是否正确；
4. `min_height` / `max_height` 是否可能切掉了所有点；
5. `range_min` 是否设置过小或过大；
6. 是否有另一段代码也输出 `/scan`。

### Nav2 不启动

1. 是否先启动了 `odom_bridge`；
2. TF 是否缺少 `base_footprint`；
3. AMCL 是否已有 map；
4. `/scan` 是否正常；
5. `nav2_params.yaml` 中的 frame 是否匹配。

### 狗不动

1. 是否 `balance_stand` / `recovery_stand`；
2. `/api/sport/request` 是否有发布；
3. `/cmd_vel` 是否有数据；
4. `twist_bridge` 是否触发安全停；
5. Go2 是否处于可运动模式。

### 日志出现 incompatible QoS / 前置急停不生效

1. `ros2 topic info /scan --verbose` 看发布端与订阅端 QoS（发布端应是 best_effort）；
2. `twist_bridge` 必须用 sensor data QoS 订阅 `/scan`，用默认 reliable 会收不到消息；
3. 收不到扫描时 `twist_bridge` 视前方距离为无穷，安全停用不会触发，日志里
   `front safety stop: x.xxm` 永远不会出现，可据此判断；
4. 确认有扫描后，再核对 `stop_distance` / `emergency_distance` 是否符合现场。

### 语音不出声

1. 是否存在 `audio/<speech_id>.wav`；
2. 在终端手动播放 `aplay audio/xxx.wav`；
3. `voice_player` 是否订阅 `/robot/say`；
4. 是否处于播放冷却期；
5. 控制电脑音频输出是否可用。

## 15. 当前限制

1. **反光条识别已实现为测试项，但未接入避障**，不会自动阻止穿越。
2. **本体播放语音未验证**，目前以控制电脑播放为主。
3. **官方话题名可能随固件变化**，现场必须以 `ros2 topic list` 为准。
4. **`return_home` 参数尚未完全展开为独立的状态**，当前低电量返航复用第一个航点。
5. **Go2 底盘运动不等于履带车辆**，Nav2 costmap 的几何模型只能近似，必须现场保守标定。
6. **Windows 端测试只覆盖 Python 逻辑**，不覆盖 Unitree/ROS 2/Nav2 真机行为。
7. **官方 `slam_operate` 后端尚未实现**：当前只有 `unitree_ros2 + Nav2` 路线；若确认使用 EDU + 拓展坞 + MID-360/XT16，再新增 `official` 后端和 `unitree_slam_client`。

## 16. 反光条虚拟墙测试项

当前已新增一个测试用途的独立包：

```text
go2_patrol_reflective/
```

它不会影响主巡检流程，只用于验证机载 4D 雷达（L1/L2）点云能否识别高反射线状目标。

### 16.1 先确认字段

```bash
ros2 topic echo --noarr /utlidar/cloud_deskewed --once
```

必须包含以下字段：

```text
x
y
z
intensity
```

如果缺少 `intensity`，本测试功能不会工作。

### 16.2 启动测试

```bash
source ~/go2_official_ws/scripts/setup.sh
ros2 launch go2_patrol_reflective reflective.launch.py
```

查看状态：

```bash
ros2 topic echo /reflective_wall_status
ros2 topic echo /reflective_wall_active
```

正常输出应为：

```text
active=true markers=1
```

### 16.3 RViz 查看虚拟墙

 RViz 添加：

```text
Display type: MarkerArray
Topic: /reflective_wall_markers
```

默认是橙色矩形，用于标记点云中检测到的高反射线段。

### 16.4 当前测试参数

| 参数 | 默认值 | 说明 |
|---|---:|---|
| `intensity_min` | 30.0 | 反射强度阈值，必须现场标定 |
| `height_min` | -0.10m | 保留地面附近反射点 |
| `height_max` | 0.10m | 测试范围较窄，便于确认条带 |
| `max_range` | 6.0m | 不考虑远处点 |
| `cluster_eps` | 0.18m | 聚类邻域 |
| `cluster_min_points` | 3 | 起始簇最少点数 |
| `min_line_points` | 5 | 拟合线段最少点数 |
| `inlier_distance` | 0.08m | RANSAC 内点容差 |
| `required_hits` | 3 | 需连续 3 帧命中才激活 |
| `wall_half_width` | 0.10m | 测试 Marker 厚度 |
| `wall_height` | 0.70m | 测试 Marker 高度 |

### 16.5 输出话题

```text
/reflective_wall_markers   # 测试虚拟墙 MarkerArray
/reflective_wall_active    # false / true
/reflective_wall_status    # 可读状态字符串
```

### 16.6 未完成的部分

当前只是测试项，**还没有正式接入 Nav2 costmap**。因此机器人不会自动避让这些 Marker。完成测试后，需要：

1. 先获取最低和最高的真实反射强度；
2. 现场标定 `intensity_min`；
3. 验证长时间误检率；
4. 把几何约束线段转换成 official-compatible `PointCloud2`；
5. 再作为 `obstacle_layer` observation source 加入 `nav2_params.yaml`。

如果现场无 `intensity`，不要继续实时识别，可改为地图禁行区。

在此测试通过之前，该功能只用于查看是否检测得到，不能作为安全避障。

## 18. EDU、L2 与官方 SLAM 导航服务（选型必读）

本节只做结论汇总，完整对比见 [`EDU与L2-官方SLAM导航服务对比.md`](EDU与L2-官方SLAM导航服务对比.md)。

### 18.1 机载雷达是 L2，不是 L1

- 当前新款 Go2 产品页写明：机载 **Unitree 4D LiDAR L2**，360°×96°，
  最小探测距离 0.05m；L2 单品页标称 64000 点/秒。
- 旧批次 Go2 和旧资料写的是 L1（360°×90°，21600 点/秒）。
- L2 周向扫描频率为 5.55Hz（可定制），比 L1 的 11Hz 慢，但单圈点数约
  11500（L1 约 2000）。自动巡检速度先按 0.3～0.6 m/s 验证急停距离，
  不要因为点云更密就默认可以跑快。
- 两者的 SDK 话题接口一致，本工作空间不用改代码结构，只需现场确认
  `/utlidar/cloud_deskewed` 的真实频率、点数和 `intensity` 字段。

### 18.2 官方 `slam_operate` 不使用机载 L2

宇树官方 SLAM 导航服务接口明确要求：

> EDU + 拓展坞 + 宇树官方购入的外置雷达（MID-360/XT16）

因此有三种配置：

| 配置 | 导航方案 | 反光条能否当墙并自动绕行 |
| --- | --- | --- |
| EDU，仅有机载 L2/L1 | 本工作空间：`slam_toolbox + AMCL + Nav2` | 可以，后续接入 costmap |
| EDU + 拓展坞 + MID-360/XT16，走官方服务 | 官方 `slam_operate`，PCD 地图 + 1102 位姿导航 | 不可以，只能暂停/告警 |
| EDU + 拓展坞 + 外置雷达，但坚持自研 Nav2 | 自己的雷达驱动 + Nav2 | 可以，工程量最大 |

### 18.3 如果切官方服务，代码要改什么

1. 新增独立进程 `unitree_slam_client`，用 Unitree SDK2 调用
   1801/1802/1804/1102/1201/1202/1901；
2. `patrol_manager` 增加 `backend=official|nav2`；
3. 到点语音保留：订阅 `rt/slam_key_info` 的 `is_arrived`，
   继续发布 `/robot/say`；
4. 地图从 `map.yaml` 改成 PCD 路径；
5. 航点必须拆成 ≤10m 的短直线段，速度限制 0.2～0.8 m/s；
6. 官方服务与 ROS 2 在同一环境有 DDS 冲突，不能简单混跑。

### 18.4 官方服务的场地限制

- 适用：小于 25m×25m、特征丰富、静态室内平地；
- 目标点距离不超过 10m，机器人沿直线行走；
- 障碍物高度不低于 20cm；
- `mode=1` 停障；`mode=0` 绕障要求通道 ≥0.8m、障碍宽度 <0.5m；
- 官方建议连续使用不超过 30 分钟，避免拓展坞 CPU 降频导致定位异常。

### 18.5 结论

- **只做巡检 + 到点语音**：有拓展坞和官方外置雷达时，可以切官方服务，
  代码量反而减少；
- **反光条必须当墙并自动绕行**：不要切官方服务，继续用本工作空间的
  Nav2 方案；
- **只有 EDU + 机载 L2**：本工作空间现有方案完全适用，不需要外置雷达。
